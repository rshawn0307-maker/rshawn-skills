# 内容策略与写作规范（references/content-strategy.md）

> 本文件在 SKILL.md 步骤 2（写内容草稿）和步骤 2.5（祛 AI 味儿）时读取。
> 2026-09-06 修订：面向"懂框架但答得空"的考生，一期一技巧 + 边界声明。
> 2026-09-08 修订（v2.2.0）：点评必须有据（批评对应普通版原话）、读源与审稿记录必填、
> 标题"考官想听的"降为候选句式、练习升级为新场景迁移任务、修正"一律删条件词"红线。
> 吸睛来自具体问题，专业感来自解释；不靠虚构权威（"考官内心"、无出处统计、一票否决）撑可信度。
> 模板契约（14 字段 / 18 段 / 字体 / 配图 / 引流段）见 SKILL.md「模板铁律」，本文件只管内容。

## 定位

教一个具体改法：读者读完知道**自己卡在哪、这期学会什么、回到题目怎么改**。
所有内容服从一期一个主要技巧；原方法其余知识点最多一句带过作背景。

## 读源与审稿记录（draft_meta.json，必填，不进模板）

每期动笔前从方法论/讲义/题库原文提炼，写进草稿工作区的 `draft_meta.json`。**必填**：
content_rules.py 自 v2.0 起对缺记录/记录不全/审稿未通过的稿件一律拒绝放行。

| 字段 | 说明 |
|------|------|
| skill_version | 技能版本（当前 2.2.0）；旧成稿以此回溯是哪版规则产出 |
| method_points / point_labels | 原方法实际要点数（两点就是两点，五点就是五点）与要点标签 |
| sources | 出处列表，"文件#小节"；点评和边界表述须能追溯到这些原文 |
| quote_excerpts | 来源摘录：点评、边界所依据的原文短句，一条一条抄 |
| applicable_conditions | 适用条件；教师注里的权限/安全提示必须原样保留在此 |
| shared_context | 共同题境：对照两版共用的题干身份、事实和问题，逐项写清 |
| key_change | 关键改动：本期对照唯一展示的那处变化 |
| actionable_demo | 可照做示范：至少一个抽象要点展开成的具体问句/判断/动作（含能直接问出口的原句），并写明答案将如何影响下一步 |
| exercise_criteria | 练习判据：新场景任务 + 2-3 个自检要素；确认题目所需知识已在正文讲清 |
| title_candidates | 3 个候选标题（痛点式/具体改法式/原栏目式各一）与选择理由 |
| review_conclusion | 审稿结论：独立审稿五项全过才写"通过"；**没有"通过"不得进发布流程，不得标记合格** |

资料有冲突时回查具体原文裁决，不自行拼出新口诀；不修改本地教学原文。

## 字段写法

### 1. 标题（tip_title）

- **≤20 字**（脚本硬上限，含前缀），能看出解决什么问题。
- **候选句式（2026-09-08 起，"考官想听的：xxx"不再是强制句式）**：内部产出 3 个候选——
  痛点式（读者卡点直说）、具体改法式（方法收益直说）、原栏目式（`考官想听的：xxx`，前缀 6 字）——
  比较后只输出 1 个，候选与理由记入 `title_candidates`。
- xxx/标题主体写实具体：疑问、痛点、明确收益均可；禁止无依据的提分承诺（"听完必上岸"类）。
- **标题必须在正文兑现**：标题问什么，破题/步骤/对照就要答什么。
- 封面文本框只放标题本身，不写"每日一练""第 N 期"等栏目词（"结构化答题技巧："前缀由引擎自动加）。

### 2. 破题（question_type + tip_intro）

- question_type：说明什么题境下会遇到这个问题（"适用题型：组织计划题·调研类"）。
- tip_intro：直接交代本期方法，一个判断句讲清；**点明本期边界**（"这期只教X"）。
- **题骨前提保留一句**：与所教技巧同题的必要前提（应急的安全排查第一、调研的先摸底数、纠错的先核实事实）在破题或避坑里点一句，防止读者学到残缺骨架。
- 用"考官想听的："作标题属栏目化句式，不算虚构权威；但正文仍不替考官编内心独白（"考官内心：…"）、不写无依据评分规则（"一票否决""听了就加分"），涉及数字必须有出处，否则改定性描述。

### 3. 思路 3 步（step1-3）

- **三个段位不等于三步方法**：
  - 原方法两点 -> step1/step2 讲透这两点，step3 写应用或检查，不凭空造第三点。
  - 原方法四点及以上（含五点）-> 按原逻辑分组进三步，关键条件一个不删。
  - 原方法三点 -> 1:1 对应。
- 每步含一个**判断、动作或检查方法**，让读者能照做；不写"高度重视""全面了解"。
- **方法要教到能照做（2026-09-08 起）**：每期至少把一个抽象要点展开为**能直接问出口的具体问句**
  （如"最近一次去医院，出行是谁帮忙安排的？"），并说明答案将如何影响下一步
  （"答出靠家属安排的，优先补出行支持"）。只列主题词（送餐、就医、安全监护）不算教过。
- 案例中的推测写明是**待核实方向**（"先按 X 猜想核实"），不把猜测写成既成事实。

### 4. 普通 vs 高分对照（case_*）

- **同题、同身份、同条件**：两版回答的是同一道题的同一问，共用身份、事实、问题记入
  `shared_context`。改进版不得偷加题干里没有的事实，也不得单靠篇幅取胜
  （**去前缀后长度不超过普通版的 1.5 倍**，程序按 1.5 拦）。
- **聚焦一个关键改动**：对照只展示本期技巧造成的那处变化（记入 `key_change`），其余部分两版保持同级水平。
- 普通版是**可信的常见答法**（读者会有"这就是我"的共鸣），不是稻草人。
- **点评必须有据（2026-09-08 起，重点规则）**：
  1. 每条批评都要能对应到普通答法里的**一句原话**（点评可引用该句；程序检查点评与原话共享实词）；
  2. 区分**"没有说明X"（信息缺失）与"说错了X"（内容错误）**：原话没承诺时间，就不能批"随口保证"，
     只能批"没给下一次消息安排"；
  3. 点评不得引入普通版没有的指控（指控词在原话里找不到对应表述即"批评无据"）；
  4. 定性判断配机制解释，不做全称断言（"群众等的不是电"这类绝对化表述，
     改成"很多人最想听到的是一句确定的消息"或删掉）。
- 点评说清**哪个动作、判断或表达变了、为什么有效**，能追溯到读源记录的关键动作。
- 不写"考官内心：…"、不给考官安想法；示范答法如用第一人称，须能让读者看出是示范，不冒充作者经历或真实考场反馈。

### 5. 避坑提醒（pitfalls）

- 写三类：**适用边界**（什么情况这招不适用/要调整）、**常见误用**（读者容易怎么用歪）、**纠正动作**（用歪了怎么拉回来）。
- 教师注的权限/安全提示必须吸收（如"容缺以事项规则为准""电气操作交专业人员"）。
- 纠正"空泛官话"时给出替换写法，不把正常公考用语一律当禁词。

### 6. 一句话总结（tip_takeaway）＝新场景微练习

- **一道新场景迁移任务（2026-09-08 起）**：换一个正文没出现过的场景，让读者把本期方法用一遍，
  并附 **2-3 个自检要素**；题目所需知识必须已在正文讲清，不要求读者翻回原讲义才能作答。
- 自检要素里至少一个指向**适用判断**（这个场景该不该用、要不要调整）。
- "自检一下你上次的答案"这类回顾式练习不满足要求；纯反问（"是不是心态更重要？"）不是练习。
- 不写感想式收束（"说到底面试考的是心态"这类读者带不走的话）。

### 7. 话题标签（hashtags）

- 5-8 个，空格分隔，每个以 `#` 开头。
- 固定 3 个：`#公考面试 #结构化面试 #上岸`；其余按当期题型/主题补 2-5 个。
- 只用与本期内容相关的标签，不蹭热门。

### 8. 段落节奏（所有正文段）

- **单段 ≤4 行，行内 ≤30 字**；短句 8-20 字为主，长句必须拆。
- 数字一律阿拉伯数字。
- emoji 每段 ≤2 个，限调色板：`❗️ 🙅 ❌ ✅ 📌 💡 ⏰ 🗣`。
- 不靠"第一/第二/第三"连接词撑场面。

## 吸睛与可信度

- **吸睛来自具体问题**：标题和破题把读者真实卡点说出来，就够抓人；反转、金句可用可不用，一期最多一处"不是 X，是 Y"。
- **金句不做绝对化断言**：顺口的"第一句话定成败""群众等的不是电"属于全称判断，没有依据不写；
  有依据的判断要敢下，但把推测说成确定事实不行（见去 AI 化红线"武断与过限定"）。
- **专业感来自解释**：每个"别这么做"都跟着"为什么"；每个"这么做"都有出处或示范。
- 数字钉子必须有出处或标"举例"；**禁止编造百分比和统计**；引用外部来源时，
  来源必须与读源记录 `sources` 对得上，编造"据某调查"直接拦截。
- 听感自检：写 JSON 前把全文大声读一遍；书面连接词（此外/值得注意的是）、破折号一律改口语或清零。

## 实质审稿（程序自检之外，必做）

**分工**：content_rules.py 只管字段、长度、来源完整性、线索词；它认词语线索，**不能替代语义审查**。
以下五项由独立审稿（换一个不带写稿记忆的视角，或另一个评审代理）逐项核：

1. **标题兑现**：标题问的，正文答了；不是只列方向。
2. **点评依据**：每条批评对应普通版原话；无凭空指控、无偷换身份/条件；
   "没有说明"与"说错了"分得清。
3. **方法含义**：步骤与原文方法一致，边界内关键条件未丢；抽象要点至少一个展开到能照做。
4. **边界**：适用/不适用/教师注齐；正常条件词没被当成 AI 味删掉。
5. **练习可作答**：新场景任务所需知识正文已讲清；遮住高分答法，审稿者也能按步骤完成该动作。

审稿结论写入 `draft_meta.review_conclusion`；**没有"通过"不得进步骤 3，不得标记内容合格**。
审稿发现的问题回到对应字段改，改完重审。

## 手机阅读与渲染验收

- 生成后做渲染检查。本机无 Word/WPS/LibreOffice 时，textutil + 无头 Chrome 是**近似渲染**：
  只能验证内容顺序、分页长度和明显溢出，**不能证明**发布图片的实际字号与阅读顺序。
- 检查项（按约 375 像素手机显示宽度）：无截断、无重叠；对照与点评的对应关系一眼可辨；
  关键内容不依赖放大阅读。
- 内容过密时删重复解释、压缩文字长度，**不删除关键条件**。
- 结论记入 `draft_meta.render_check`：如实标注"近似通过"或"发布端通过"；
  只有近似结果时，发布前需在发布端复核一遍才算闭环。

## 效果复盘（发布后）

- 每篇发布后第 7 天，把数据记入项目根 `scripts/tips_metrics.json`：
  skill_version、题型、学习卡点、发布日期、阅读数、收藏数。
- 复盘口径统一：**收藏率 = 收藏数 ÷ 阅读数**；同时看阅读量，低阅读会造成比例虚高。
- 先积累同系列基线（同版本规则下至少数篇），再判断改动是否有效；
  不设未经验证的"爆款及格线"，AI 评审结果不能代替真实读者的收藏行为。

## 去 AI 化红线

**流程**：生成草稿 -> 按 human-writing 规则自查 -> 改写问题片段 -> **回核读源与审稿记录（术语/条件/方法含义不丢）** -> 跑 content_rules.py（--meta 必填）-> 独立审稿 -> 入 JSON。

**边界（冲突处理）**：human-writing 的"正文严禁冒号"等通用红线**不约束本 skill 的固定格式**。字段前缀（"适用题型：""第一步：""普通答法：""点评：""避坑提醒："）与 hashtag、emoji 摆位是模板契约，只对各字段**冒号后的正文措辞**做去 AI 化，不得动前缀、不得删改 hashtag、不得给标签行加标点。

**绝对禁止的 AI 模式**（公考面试语境下高危版）：

| 类别 | 红线示例 | 改写 |
|---|---|---|
| **填充短语** | "为了实现这一目标""值得注意的是" | 直接说事 |
| **AI 词汇** | 此外、至关重要、深入探讨、凸显、复杂性 | 用具体动词和名词 |
| **否定式排比** | "不仅...而且..." 连用 | 改直接陈述 |
| **三段式法则** | 把 2 件事扩成 3 件凑数 | **2 件就 2 件，4 件及以上按原逻辑分组，不为凑三步造点** |
| **破折号** | "--" 出现 | 一律清零，改逗号或句号 |
| **模糊归因** | "专家认为""考官普遍反映" | 给出具体出处（须与 sources 对得上）或直接删 |
| **武断与过限定**（2026-09-08 修正） | 把推测说成确定事实（"考官一定会…""第一句话定成败"）；反过来，有依据时又事事"可能、或许"含糊到底 | **有依据的判断直接下**；真实不确定处**保留条件词**（"可能""若"），并说清不确定的是什么；推测标"待核实" |
| **通用积极结论** | "未来可期""前景光明" | 换成新场景微练习 |
| **虚构权威** | "考官内心""听了就加分""一票否决"、无出处统计 | 说方法和机制，不替考官发言 |

**特别禁用公考 AI 高危词**（一字不差）：
- **"体现/彰显/凸显"** -> 改 "X 表明" / "X 是因为" / 直接说事实
- **"深入推进/全面落实/持续优化"** -> 给出谁、什么时间、做什么
- **"多措并举/综合施策/协同推进"** -> 列出具体几条
- **"切实保障/有效提升/有力推动"** -> 给出可量化指标

**条件词不是 AI 味**：删"可能会"之前先问一句——这个不确定是真实的吗？
真实的不确定（恢复时间未知、是否处理由领导定）必须保留条件表述，删了就是教错。

## 公考词汇合规

| 类型 | ✅ 用 | ❌ 别用 |
|---|---|---|
| **政策概念** | "放管服改革""一网通办""网格化治理" | 自创缩写、没出处概念 |
| **角色** | "街道办""网格员""社区民警" | "基层干部""人民群众""相关部门"（泛指时） |
| **动作** | "设 1 个'陪同扫码岗'""保留 3 个现金窗口" | "加强 / 完善 / 推进 / 落实"（光杆动词） |
| **判断** | 敢下判断并给机制解释 | "X 是因为 Y" 的伪因果 |

## 选题策略

1. 用户指定题型 -> 过滤索引；未指定 -> 题型轮转（**同等条件下**的排序依据，不是硬性顺序）。
2. 候选按**具体学习障碍**筛选：读者卡在哪里、这期教会什么、本地依据是什么；答不上不进候选。
3. 查索引 `_meta.dedup_notes`，不按已发布角度重复出题。
4. 索引摘要与原文不符时，以原文为准并先修索引。
5. 避免过于专业的岗位题材（除非用户指定）。
