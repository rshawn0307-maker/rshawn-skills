# 结构化答题技巧·每日一练

## 适用场景

用户做"公务员结构化面试·答题技巧"系列小红书爆款图文帖子（如"应急应变别平均用力""综合分析别停在现象层"），需要：

1. **出一个答题技巧**（上岸过来人 + 考官视角，有观点、可操作、接地气）
2. **按小红书节奏打磨**（标题钩子/短句/emoji/普通 vs 高分对照/避坑提醒/话题标签）
3. **自动套入固定 docx 模板**（18 段，含配图 + 引流段）
4. **保留模板所有版式**（封面文本框、蓝色标题、引用块、尾注样式、引流段样式）
5. **从题库索引选题**，已完成技巧不重复推

## 内容骨架（每期固定 14 字段）

内容顺序（样式细节以「模板铁律」段位表为唯一契约，不在此重复）：

```
封面钩子标题（≤20 字）-> 适用题型 -> 技巧一句话（破题）-> 思路 3 步
-> "怎么答？"-> 普通答法 vs 高分答法（同题对照）+ 各自点评
-> 避坑提醒 -> 一句话总结 -> 话题标签
-> [固定引流段：模板自带，引擎不动]
```

### 字段职责（内容层，2026-09-06 修订）

14 个字段、18 段结构、字体、配图、引流段等**模板契约一律不动**，只调整各字段的内容职责。面向"懂框架但答得空"的读者，每期交付一个能马上练、能迁移到其他题目的小技巧：

| 字段 | 内容职责 |
|------|----------|
| tip_title | 定稿句式 `考官想听的：xxx`（2026-09-07 用户选定）：前缀 6 字 + xxx ≤14 字，共 ≤20 字（引擎硬上限），xxx 点出具体卡点或收益；**正文必须兑现标题承诺** |
| question_type + tip_intro | 交代什么题境下会遇到这个问题，直接点出本期方法 |
| step1-3 | 把方法教清楚，每步含一个判断、动作或检查方法；**步数服从原方法，不为凑三步硬造** |
| case_normal / case_high | 同题、同身份、同条件，聚焦**一个关键改动**；改进版不偷加题干事实、不靠堆字取胜 |
| case_normal_note / case_high_note | 指出哪个动作、判断或表达变了、为什么有效；不写"考官内心"式推测 |
| pitfalls | 写**适用边界、常见误用和纠正动作**，不只列禁句 |
| tip_takeaway | 一道微练习或可立即使用的自检问题，不再是感想式总结 |
| hashtags | 数量契约不变（5-8 个），只用与本期内容相关的标签 |

### 一期一技巧（硬规则，含试点修订 2026-09-06）

- 每期只教**一个主要技巧**：标题、破题、对照、练习都围绕它。原方法里的其余知识点最多一句带过作背景。
- **聚焦必须带边界声明**：破题点明"这期只教X"；与所教技巧同题的题骨前提（如应急的"安全永远第一步"、调研的"先摸底数"）保留一句作背景，防止读者学到残缺答题骨架。
- **忠实度口径**：本期所教技巧在其边界内不丢关键条件（含教师注的适用条件，如"是否处理由分管领导决定"）；未覆盖的要点宁可一句点名不展开，也不得教错。
- **三个段位不等于三步方法**：原方法只有两点时，step1/step2 讲这两点，step3 用于应用或检查，不得凭空造第三点；原方法有四点及以上时，按原逻辑分组呈现进三步，不得删掉关键条件。
- 吸睛来自具体问题（疑问、痛点、明确收益，画面感强的比喻同样可用），不强制反转句式、数字和金句；不写无依据的提分承诺。
- 模拟例子标为示范，不冒充作者经历或真实考场反馈。

## 工作流（6 步）

### 步骤 1：查索引选题（一次给 2-3 个候选）

从**项目根** `scripts/tips_index.json` 的 tips 里挑**未出现在 `progress_tips.json` done_ids** 的技巧：

- 用户指定题型 -> 过滤该题型；未指定 -> 按题型轮转（综合分析->应急应变->人际关系->组织计划->自我认知->言语表达->通用）
- 一次选出 **2-3 个候选**，用弹窗选择题让用户挑（选项即候选 + "都不要，换一批"），**不要让用户打字**
- 索引外补充热点技巧时须在 JSON 里 `added:true` 标记
- 候选必须能说清三件事：**读者卡在哪里、这期教会什么、本地依据是什么**（src 文件 + 方法论）；说不清的不进候选
- 检查索引 `_meta.dedup_notes`：换标题重复讲同一技巧的条目按记录的分工出题，不重复已发布角度
- 找不到支持原文的条目（src 错链/原文已更新未同步）不进候选，先修索引

### 步骤 1.5：写前读源（必做，缺此不动笔）

定题后、写稿前，**必须回读原文**，不能仅凭索引摘要写稿（索引只用于选题定位，摘要可能滞后于原文更新）：

1. **方法论**：读 `02-Areas/公考面试结构化培训/02_答题方法与框架/各题型方法论/<题型>_方法论提炼.md`（按 tips[].types[0] 映射）
2. **课堂讲义**：读讲义 `公考面试结构化备考讲义.md` 中该题型章节的对应小节（方法论要点 + 例题）
3. **题库案例**：读 src 指向的题库原文全文（题干、思路大纲、答题逐字稿）
4. **教师注**：题库原文末尾的教师注是适用条件，保留进本期"避坑/边界"，不得省略

内部记录四要素（写进草稿工作区，不进模板）：**原方法是什么、适用条件、关键动作、出处**（文件+小节）。资料有冲突时回查具体原文裁决，不自行拼出新口诀；不修改本地教学原文。

### 步骤 2：写技巧内容（14 个字段）

内容规范（详见 `references/content-strategy.md`，以 2026-09-06 修订版为准）：

- **标题 ≤20 字**（引擎硬上限），采用定稿句式 `考官想听的：xxx`（前缀 6 字计入上限，xxx 点出具体卡点或收益）；正文必须兑现标题承诺
- **一期只教一个主要技巧**，其余知识最多一句背景带过
- **单段 ≤4 行，行内 ≤30 字**，短句 8-20 字为主
- **emoji 每段 ≤2 个**，限调色板 `❗️ 🙅 ❌ ✅ 📌 💡 ⏰ 🗣`
- **普通 vs 高分对照**：同题、同身份、同条件，聚焦一个关键改动；普通版是可信的常见答法，改进版不偷加题干事实、不靠堆字取胜；点评说清哪个动作/判断/表达变了
- **避坑提醒**写适用边界、常见误用和纠正动作（教师注里的权限/安全提示必须吸收进来）
- **一句话总结**改成一道微练习或自检问题
- **话题标签 5-8 个**，固定 `#公考面试 #结构化面试 #上岸`，其余按题型补，只用相关标签
- 数字必须可核验或有出处，无出处的统计一律不写；模拟例子标"示范"，不写"考官内心""听了就加分"等推测

### 步骤 2.5：去 AI 味儿（必跑）

写完初稿 -> **必跑 human-writing** -> 才能进 pending_tips.json。硬步骤，不可跳过。

重点扫：公考 AI 高危词（体现/彰显/凸显/深入推进/全面落实）、三段式凑数、破折号清零、否定式排比最多 1 处、模糊归因、万能收束。

**边界（冲突处理）**：human-writing 的"正文严禁冒号"等通用红线**不适用于本 skill 的固定格式**。各字段前缀（"适用题型：""第一步：""普通答法：""点评：""避坑提醒："）是模板契约的一部分，human-writing 只改**冒号后的正文措辞**；不得动前缀、不得删改 hashtag 内容与数量、不得给标签行加标点、不得动 emoji 摆位。

**优先路径**：触发 human-writing skill 对 14 个字段逐个/合并重写。**降级**：调用失败时按 content-strategy.md「去 AI 化红线」手动改写，并在工作目录写 `human-writing_fallback.txt` 标注。

**去 AI 味后回核原方法（必做）**：改写完成后对照步骤 1.5 的读源记录再过一遍——术语、条件和方法含义不能在改写中丢失或走样；纠正空泛表达，但不把正常公考用语一律当禁词误杀；关键条件缺失就补回，宁可少"顺"一点也要保方法完整。

**内容自检（进 pending 前必跑）**：

```bash
python3 <本skill目录>/scripts/content_rules.py --pending <pending路径> [--meta <draft_meta路径>]
```

退出码 0 才进步骤 3；非 0 按报错改内容。覆盖：标题兑现、对照条件一致、两点/四点方法、适用边界、无虚构推测、总结是练习。

**🔴 CHECKPOINT · STOP** -> 把前后对比关键改写点（3-5 处）展示给用户，弹窗确认（"够自然，继续" / "还是像AI，再调"）。

写入 `<项目根>/scripts/pending_tips.json`（UTF-8 无 BOM）。schema（全部非空字符串，缺一/多一都会被引擎拒绝）：

### 步骤 4：跑引擎（唯一执行入口）

```bash
python3 <本skill目录>/scripts/fill_tips_post.py --project-root "<项目根>"
```

退出码契约：

| 退出码 | 含义 | 处理 |
|--------|------|------|
| 0 | 成功，模板已原子替换，pending 已清理 | 进步骤 5 |
| 1 | 环境错误（pending 缺失 / 模板缺失或损坏） | 修环境后重跑，模板未被动过 |
| 2 | pending JSON 无效（语法 / UTF-8 / 缺字段 / 多字段 / 标题超 20 字） | 按报错改 JSON 后重跑 |

| 4 | 模板已替换但 pending 清理失败 | 模板已**自动回滚**为写入前字节，pending 保留；修 scripts 目录权限后重跑即可 |

**安全保证**：引擎先写临时文件、验证（结构 + 内容 + 逐段样式指纹 pPr/rPr 零漂移）通过后才原子替换模板；任何失败（含退出码 4 的清理失败，自动回滚）模板字节不变，pending 保留排查。写入前自动生成快照。

### 步骤 5：更新完成记录 + 报告

1. 把本次技巧 id 追加进**项目根** `scripts/progress_tips.json` 的 done_ids
2. 报告：技巧标题 + 题型 / docx 路径 / 引擎验证结果（exit 0 = 段数 18 / 图 4 / 样式 / 14 字段全命中）/ 去 AI 味儿自评

### 步骤 6：上传 IMA（可选，仅用户明确要求时执行）

**默认不做**。只有用户明确说"同步/上传 IMA"才执行：

1. 构造标题 `{技巧关键词}_{YYYYMMDD_HHMMSS}`，把步骤 3 内容格式化为 Markdown（H1 为标题）
2. 写临时 md 到系统临时目录，调用：


## 模板铁律（唯一结构契约）

**字体铁律**：模板字体已统一为通用字体，不要引入云字体或内嵌字体文件。段位/样式/脚本行为全部以此表为准：

| 段位 | 内容 | 引擎行为 |

## 失败处理

1. **不要慌**：引擎任何失败都不会写坏模板（原子替换 + 失败字节不变）
2. 看退出码和 `[ERROR]` / `[FAIL]` 信息定位（字段名、上限、段位都点名）
3. pending 在失败时保留，改完直接重跑
4. 需要人工回退时：从 `<项目根>/scripts/_snapshots_tips/` 复制最新 snapshot 覆盖回模板路径

## 脚本行为要点（避坑）

1. **不预设 run[0] 是文本 run**：找"第一个纯文本 run"写入，图片 run 完全不动
2. **封面改 2 处**：drawing 镜像 + VML fallback 都要同步
3. **emoji 由引擎自动加**：段[8] 🙅♂️、段[10] 👍 写在 EMOJI_PREFIX 里，别写进 JSON
4. **段[3] 首行缩进 2 字符**（firstLineChars=200），段[9]/[11] 浅灰底色不动 shd
5. **看 docx 段数**：`python3 -c "from docx import Document; print(len(Document('路径').paragraphs))"`
6. **看文本框/图片/分页**：分别搜 `<w:txbxContent>` / `<w:drawing>` / `<w:pageBreakBefore>`
7. **写 json 用 Python `json.dump`**，避免手写引号嵌套错
8. **样式指纹零漂移**：引擎写入前后逐段对比 pPr/rPr XML（含封面文本框内段落），任何字体/字号/颜色/对齐变化即验证失败（exit 3），杜绝"文本对了样式坏了"的假绿
