# 预设：微信公众号 / 网页长文

> ## ⏱ 时效声明
>
> **数据核验日期：2026-09-17**　核验渠道：微信公众号编辑器行为与屏幕阅读惯例。
>
> **使用本预设前，必须核对它是否仍与最新标准/惯例一致。** 分两种情况处理：
>
> - **用户只是想在预设基础上改个别参数**（字号、边距、行距等）→ 直接改，不必去查标准。
> - **用户指出某条规定已变化，或距核验日期已超过 12 个月** → 必须复检，不得沿用本文件：
>   1. 先请用户提供出处（标准原文、学校/单位最新模板、期刊投稿须知）；
>   2. 用户拿不出出处时，联网到官方渠道复查；
>   3. 确认后把结论写进你自己那份 `standards.md`（路径问 `python3 scripts/user_data.py --path standards.md`），
>      并更新规格卡的 `verified_at` 字段。**要改这条预设本身，先另存一份到用户预设目录再改** ——
>      直接改出厂预设，下次更新 skill 就被覆盖了。
>
> **复检渠道：**
> - 公众号编辑器会过滤的 CSS 属性随平台更新而变，**每次使用前建议先用一段样例粘贴验证**
> - 微信对正文字号、图片尺寸、外链的限制以公众号后台最新说明为准
>
> **提示义务：** 展示本预设时，要主动告诉用户「这份预设是 X 年 X 月核验的，
> 如果你手上的模板/须知与它不一致，以你手上的为准」。不要默认预设一定正确。

## 一、核心认知：屏幕排版与纸张排版是两套逻辑

**这是最容易搞错的一条：手机阅读的排版习惯和纸质书相反。**

| 项 | 纸质书 | 手机屏幕 |
|---|---|---|
| 段落区分 | 首行缩进 2 字符 | **段间距**（缩进在窄屏上浪费行宽） |
| 字号 | 五号（10.5pt） | 15-16px（约 11-12pt） |
| 行高 | 固定值 15.6pt | **1.75 倍**（中文行高大，屏幕上行挤会累） |
| 页边距 | 20mm 左右 | 左右各 16px 内边距 |
| 对齐 | 两端对齐 | **左对齐**（两端对齐会产生难看的字间距） |
| 插图 | 居中，配图注 | 宽度 100%，不配图注 |

**所以：不要拿纸质书的规格去排公众号。** 如果同一篇稿子要出两个版本，必须分别套两套规格。

## 二、用中文向用户介绍这个预设

```
微信公众号 / 网页长文（屏幕阅读）

  正文字号    15-16px
  行高        1.75
  字色        #3F3F3F（纯黑在屏幕上刺眼）
  段落区分    段间距 1em，不用首行缩进
  对齐        左对齐，不用两端对齐
  左右内边距   各 16px
  小标题      17-18px，加粗，段前段后留白
  引用块      左侧竖线 + 浅灰背景 + 斜体或灰色文字
  图片        宽度 100%，圆角，上下留白
  强调        加粗或改变颜色，不用下划线（易与链接混淆）
  中英文间距   手动加半角空格，或用 CSS text-spacing

  ⚠️ 公众号编辑器会过滤部分 CSS，样式尽量内联
  ⚠️ 正文不能放外链（公众号不允许跳转外部链接）
```

## 三、必须问用户的项

| 项 | 为什么问 | 建议默认 |
|---|---|---|
| 目标平台 | 公众号、知乎、小红书、个人博客的规范都不同 | 微信公众号 |
| 主色 | 强调色、小标题色、引用块竖线色 | 询问品牌色或选一个 |
| 是否要首行缩进 | 少数公众号仍坚持缩进 | 不缩进，用段间距 |
| 正文字号 | 15px 与 16px 观感不同 | 15px |
| 正文是否含图片 | 图片粘进编辑器后需要用户自己重新上传到素材库，必须提前说明 | 逐张说明，不假装已就位 |
| 正文是否含视频 / GIF | 视频无法靠粘贴 HTML 进入正文，只能在编辑器里手动插入 | 留占位提示，提醒用户手动补 |
| 表格对齐方式 | 手机上行宽大，选错会很难看 | 默认不预设；用户要求时建议表头居中、数据左对齐（手机上数字列也左对齐） |
| 表格是否要三线表 | 部分编辑公众号时会重写表格样式 | 三线表，只用横向框线 |

## 四、YAML 参数

```yaml

  preset: wechat-cn
  name: 微信公众号
  source_type: 平台惯例
  standard: null
  verified_at: "2026-09-17"
  recheck_after: "2027-09-17"   # 超过此日期必须先复检再使用
  recheck_rule: 用户只改个别参数则直接改；引用标准变化或超期时必须联网复检并更新
  carriers: [html]

html:
  inline_css: true                # 公众号会过滤 style 标签，必须内联
  max_width_px: 677               # 公众号正文宽度上限
  allow_external_links: false     # 公众号正文不允许外链

# 屏幕阅读参数统一放在 screen 段，与 fonts.body（纸上正文字体）区分开，避免读错字段
screen:
  body:
    font_size_px: 15
    line_height: 1.75
    color: "#3F3F3F"
    text_align: left              # 不用 justify
    padding_left_px: 16
    padding_right_px: 16
    letter_spacing: 0.5px
  quote:
    enabled: true
    border_left_px: 3
    border_color: "#D0D0D0"
    background: "#F7F7F7"
    padding_px: 12
    color: "#666666"
  image:
    width: 100%
    border_radius_px: 4
    margin_top_em: 1.0
    margin_bottom_em: 1.0

paragraph:
  indent_mode: spacing            # 关键差异：屏幕用段间距
  text_indent: 0
  margin_bottom_em: 1.0

headings:
  h1:
    font_size_px: 20
    bold: true
    margin_top_em: 1.6
    margin_bottom_em: 1.0
  h2:
    font_size_px: 18
    bold: true
    margin_top_em: 1.4
    margin_bottom_em: 0.8
  h3:
    font_size_px: 16
    bold: true

figures_tables:
  # 表格对齐不预设：有 Markdown 对齐标记就用标记，用户另外要求再按用户要求写，
  # 都没有就保持默认。从前这里写过「表头居中 + 数据列左对齐」，已按用户要求取消。
  table_style: three_line             # 只用横向框线，不画竖线

emphasis:
  method: bold_or_color          # 不用下划线

  mode: manual_space             # CSS text-spacing 支持度差，改用加半角空格

# ── 结构识别规则（infer_structure.py 读取）───────────────
structure_rules:
  family: screen    # 层次序数规则族：gov（公文四级）| book（章节六级）| screen（屏幕粗分）
  detect_elements: []    # 本体裁不做公文要素识别
required_elements: []    # 本体裁无硬性内容门槛
ask_elements:    # 内容里没有、只能问用户的项
  - key: title
    label: 标题
    ask: 公众号文章标题是什么？
```

## 五、载体适配注意

| 项 | HTML |
|---|---|
| 首行缩进 | `text-indent: 0`（与纸质规范相反） |
| 段落间距 | `margin-bottom: 1em` |
| 两端对齐 | 关闭，改用左对齐 |
| 外链 | 正文禁止 |
| 字体 | 用系统字体栈，不硬指定 |
| 表格 | 只用横向框线；对齐默认不预设，按源文件标记或用户要求。编辑器可能重写表格样式，粘贴后要目视核对 |
| 图片 | 宽 100%、圆角；粘贴后需用户重新上传到素材库，HTML 里的图不会自动进素材库 |

## 六、交付给用户时必须说清的两件事

1. **图片要重新上传。** 生成的 HTML 里图片是 `<img src="...">`，粘进公众号编辑器后微信不会替用户上传，
   需要用户把图片手动传到素材库。所以交付时要说：「正文有 N 张图，粘贴后需要你重新上传一遍。」
2. **视频与 GIF 只能手动插入。** 这两类媒体无法通过粘贴 HTML 进入公众号正文，
   skill 只能在对应位置留一行占位提示，由用户在编辑器里手动补充。这一点不要默认用户知道。
