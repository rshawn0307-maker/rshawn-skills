# md 代码思维导图转图片 v1

> 用途：把 Markdown 代码围栏里的结构图转成图片，供 Word/讲义汇编使用。本文可直接复制给任意 agent；不含路径、不含技能名。

---

请将 Markdown 代码围栏中的结构图转换为图片，按以下要求执行。

## 一、识别三类代码块

1. **ASCII 树形图**：围栏内含 `├` / `└` / `┌` 等树形连接符（知识结构、关系图）→ 转“思维导图”；
2. **mermaid 流程图**：围栏内含 `graph LR` 或 `-->`（时间线、发展历程）→ 转“时间线/流程图”；
3. **其他纯文本**（如公式）：保留为等宽文本段落，不转图。

## 二、转图要求

1. **思维导图**：从左到右布局（根节点在左、子节点向右展开）；节点用圆角方框；根节点深蓝底白字，层级逐级用柔和色；层级连线清晰；
2. **时间线/流程图**：从左到右分层布局（按最长路径定层）；节点方框 + 箭头表示先后/因果；多分支脉络用不同行错开；
3. **中文显示**：中文必须完整渲染（优先 PingFang / 宋体 / Songti SC；渲染环境缺中文字体时先注入系统中文字体目录，禁止把豆腐块当正常结果）；
4. **经济优先**：字号以“能看清字”为准，分辨率默认 1 倍即可，不追求高清；图片总量尽量小；
5. **缓存**：按“内容 + 缩放参数”哈希缓存，重复构建不重渲。

## 三、必须避开的坑（实测教训）

1. **顶部留白**：布局必须从画布顶部留白（如 32px）开始排第一个节点；否则最上一行文字/边框会被画布边缘裁切——这是实测出现过的 bug；
2. **四边审计**：渲染后逐张检查图片上下左右 3px 内不得有非白像素（内容贴边即视为裁切风险）；
3. **文字不溢出节点框**：按字体实际宽度换行，框高按行数自适应；
4. **Word 插入尺寸**：显示宽度默认 ≤ 6.2 英寸；若按比例高度超过 7.5 英寸，按高度反算缩小宽度；图片居中，段前段后留约 6pt。

## 四、验证

1. 每个图代码块都有对应图片（或确认属于“非图文本”）；
2. 抽查若干图片：首行文字完整、无边缘裁切、无文字溢出方框；
3. Word 渲染抽查含图页：图片正常显示、不破版；两版（教师版/学生版）插入同一张图。
