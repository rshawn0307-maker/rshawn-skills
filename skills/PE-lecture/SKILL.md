# 举一反三讲稿 · 反例沉淀与批量产出 SOP

## 定位

体育学科「举一反三讲稿」的实战反例清单 + 批量产出/审核/汇编 SOP。主流程走 4 条工作流，反例自查走 `scripts/r1_self_check.py`，细节规范按任务路由读 `references/`。

**双源铁律**：基于 `教师招聘笔试 基础教材 体育(下册).docx` → 输出 `举一反三讲稿/`；基于 `招教 体育 讲义库.md` → 输出 `讲义库举一反三讲稿/`。两者不可混用。

## 前置条件

- 有老板项目工作区（`01_教师编体育学科教研/...`）+ 项目 Python 环境（装 python-docx + pptx + openpyxl，见 R16）。
- 有真实的讲义 .docx（≥350 行）或讲义库 .md + 目标输出路径。
- **没有老板工作区就跑不动**——此时本 skill 只能作"教学/反例参考"。

## 工作流路由

| 用户说 | 走哪条 | 产出 |
|--------|--------|------|
| "写讲稿"/"生成讲稿" | 批量产出 SOP | N 篇 .md |
| "审核某模块"/"检查讲稿" | 批量审核工作流 | 修订 .md + 报告 |
| "合并下册"/"同步 docx" | 下册 docx 同步 | 单个 .docx |

| "代码思维导图转图片" | md 代码块转图 | 图片 |

## 启动检查清单

> 🔴 STOP — 开工闸：先确认工作流路由，再完成该路线需要的输入确认；缺必要输入才停下追问。

1. **生成/从底本改写**：确认讲义 .docx/.pptx/.md 文件名与源类型。下册 docx → `举一反三讲稿/`，讲义库 .md → `讲义库举一反三讲稿/`。不明时不猜。
2. **审核/修订**：确认目标讲稿目录、模块或批次。
3. **Word 汇编**：确认输入批次、教师版/学生版需求、输出命名。
4. **路由**：见上方路由表对号入座。

## 触发来源分支（4 种讲义底本）

- **A. 有讲义 .docx** → 常规抽章节 SOP
- **B. 有 PPT .pptx** → PPT 抽取 SOP（`references/PPT无讲义处理_v1.md`）
- **C. 无讲义/残缺** → 3 种 if-then：完全无→坦白声明不编造；OCR 乱码/表格拆图→标注缺失不编造；没这知识点→坦白不硬塞 R1 补丁
- **D. 明确"无讲义基于 PPT"** → 严格按 PPT 内容写 + 顶部标"数据来源" + 「PPT」标记原话

## 写稿铁律（避免 R1 反弹）

- 引用讲义**不加任何前缀**（禁"讲义原话：/讲义原文：/原文：/教材：/讲义："），直接写引号，或 blockquote `> "..."`。
- 模块三"2. 回原文："步骤名用破折号"2. 回原文——"（R12 误报可豁免，R1_R原文 不豁免）。
- 不加"考点：模块X-Y XXX"尾巴。

## 反例自查（每篇写完必跑）

`python scripts/r1_self_check.py <dir>` 一键查 R1-R20。**脚本绿 ≠ 内容对**，必抽样核对 3 类位置（删除处括号闭合 / 改写处引出词合规 / 补题处位置与题号）。完整反例见 `references/核心反例_R1-R20.md`（R1-R8、R13-R20）。

## 批量产出 SOP（5 步）

1. **抽章节大纲定边界**：用项目 Python 环境 + python-docx 行号切片抽章节标题，临时脚本落系统临时目录。
   > 🔴 CHECKPOINT：拆解表覆盖全部小节、拆篇数符合锚点（<350→3 / 350-500→3-4 / 500-750→5 / ≥750→5-6）、无遗漏 ≥10 知识点小节。
2. **拆解表 + 报"先 1 篇过目"**。
   > 🔴 STOP：01 篇写完不直接批量，先报老板过风格/结构；任何 R1 反弹修复后都要重新报。
3. **产 01 篇 + R1 自查**（第一篇常有 R1 漏，2 轮内归零）。
4. **批量 02/03/...**：每篇写完立即跑 R1 自查 + 自动触发拓展盒审计。
   > 🔴 CHECKPOINT：R1=0（含 R6 孤冒号）+ 抽样核对 + 内容质量抽查全过。
5. **R1 总报告 + 写进本地 SKILL 反例**。

## 批量审核工作流（5 步）

1. 抽文件清单 + 跑 R1 自查（脚本说了算，不拍脑袋估数字）。
2. 列每篇违规行号 + 类型分类（写小脚本按行 grep）。
3. 抽样 1-2 篇精读内容质量。
4. 出审核报告 + A/B/C/D 修订方案（A 默认"批量 patch + 补缺漏"）。
5. 批量 patch → 二次验证 → 抽样核对（脚本 R1=0 ≠ 真合规，必抽 3 类位置）。

## 下册 docx 同步工作流（5 步）

0. **umbrella stale 预检**：实地 `find`/`ls` verify 真路径（见 `references/老板项目真路径_v1.md`），不信 SKILL 写死的路径。
1. cp 老板项目真执行件出下册版（不 cp umbrella 公共库）。
2. 5 处精准 patch（MODULES / OUTPUT / 3 处封面文案）。
3. 加 4 道校核函数 + 补 import sys。
4. clean 正则增强（R8 防御，兼容 4 种格式）。
5. 跑脚本 + 4 道校核 + 二次验证（terminal 跑，长输出不走沙箱代码执行工具）。

## md 转 Word 汇编工作流

读 `references/md转Word提示词_v1.md` + `references/老板参考版版式_v1.md`，用提示词交给 agent 执行，产出教师版（保留授课提示）+ 学生版（剔除授课提示/学习导航/编辑备注）。验收：Markdown 残留=0、Obsidian 残留=0、Heading 映射正确、学生版 0 教学标注/0 导航。命名用短名「（上）/（下）」。

## 失败恢复

| 触发条件 | 一线处理 | 仍失败时的兜底 |
|---|---|---|
| 关键路径缺失、模板契约不符或 Python 无 docx | 🔴 STOP，报告缺失/报错 | 获准后临时装 Python 包 |
| 进度/索引缺失或损坏 | 🔴 STOP，修复 | 无权威记录请老板确认 |
| 指定讲稿重复、定位不唯一或全库完成 | 🔴 STOP，列候选 | 请老板改选 |
| 讲稿事实冲突或找不到满足表格规格的考点 | 🔴 STOP，引用冲突 | 等老板裁决 |
| R1 反弹 | 每篇写完立即自查，2 轮内归零 | 见 `references/核心反例_R1-R20.md` |
| 长稿 write_file 截断或沙箱执行超时 | 长稿拆 2 段写；长输出写文件/走 terminal | 不用沙箱代码执行工具跑长 print |
