## 触发来源分支（4 种讲义底本）

- **A. 有讲义 .docx**（浙江教材）→ 常规抽章节 SOP
- **B. 有 PPT .pptx**（如网球）→ 走 PPT 抽取 SOP（`references/PPT无讲义处理_v1.md`）
- **C. 无讲义 / 残缺讲义** → 边界处理（3 种 if-then）：
  - 完全无讲义 → 坦白声明 + 不编造
  - 讲义 OCR 乱码/表格拆图 → 识别残缺段落 + 标注缺失 + 不编造占位 + 告知用户哪些知识点缺原料
  - 讲义里没这个知识点 → 坦白 + 不硬塞 R1 违规补丁
- **D. 用户明确"无讲义基于 PPT 内容生成"** → 严格按 PPT 内容写+ 顶部标"数据来源"+ 用「PPT」标记讲义原话（2026-06-15 网球 4 篇验证）

## 批量产出 SOP（5 步成体系）

### 步骤 1：抽章节大纲定边界
- 用 workbuddy venv python（见 R16）+ python-docx 行号切片抽章节标题（不全文 grep，避免 50K cap）
- 写临时脚本到 `$env:TEMP/extract_mod*.py`，跑完落 `*.txt`，再 read_file 读
- **大讲义（≥2 MB）必备**：4 运动解剖学 750 行、5 运动生理学 352 行、8 田径 1307 行均用此法

> 🔴 **CHECKPOINT 1 — 拆解表确认**:进入步骤 2 前确认 3 项:① 拆解表覆盖讲义全部小节;② 拆篇数符合 v2.6 锚点(<350→3 / 350-500→3-4 / 500-750→5 / ≥750→5-6);③ 无遗漏 ≥10 知识点小节。

### 步骤 2：拆解表 + 报"先 1 篇过目"
- ≥10 知识点拆 2-3 篇，**大模块（≥750 行）拆 5 篇**（4 运动解剖学验证）
- **v2.6 拆篇数锚点**：< 350→3 篇 / 350-500→3-4 / 500-750→5 / ≥750→5-6
- 报"先 1 篇让老板看风格/结构"——回 1 字母后**直接批量**

> 🔴 **STOP — 01 篇过目闸**:01 篇写完**不要直接批量**——先报老板过风格/结构。回 1 字母 ≠ 风格定稿,任何 R1 反弹修复后都要重新报,不能"修完接着干"。

### 步骤 3：产 01 篇 + R1 自查
- 写完稿立即跑 R1 自查（见 `scripts/r1_self_check.py`）
- 第一篇常有 R1 漏——2 轮内归零（实测 5 运动生理学 01 从 8 处→0 用 2 轮 patch）

### 步骤 4：批量 02/03/... + 自动触发拓展盒审计
- 老板确认 01 后直接批量
- **每篇写完立即跑 R1 自查**（v2.6 修订——不要等批量完一起查）
- **最后一次性跑 R1 严格自查**（含孤冒号）——本次 5 运动生理学 02/03 共 4 处违规 2 轮修完
- 🆕 **每篇写完立即自动触发拓展盒审计**（2026-06-25 升级,见 E 章节 5 步工作流）——无需等用户指令
- 🆕 **每模块写完后,自动汇总审计报告**（拓展盒总数/遗漏/已补,见表 E）

> 🔴 **CHECKPOINT 2 — R1 全清 + 抽样核对**:批量完 ≠ 全部清。必须:① `r1_self_check.py` R1=0(含 R6 孤冒号);② 抽样 3-5 处核对(参"抽样核对硬约束"小节);③ 内容质量抽查(对比表/解题思路/题量/口诀/押韵)。全过再进结清报告。

### 2. 命名 + 目录结构

- **文件命名**:`{编号}-{章节}-{版本}.md` 风格,例:`01-绪论-v1.md`
- **目录结构**:每个模块一个文件夹,例:`讲义库举一反三讲稿/1运动解剖学/01-绪论-v1.md`
- **模块编号**:讲义库第一模块用 `1`,与原"4运动解剖学"目录命名对齐

### 3. 引用讲义原文硬约束

- **不加任何前缀**(禁用"讲义核心句:"/"讲义给出:"/"讲义原文:"/"讲义描述:"等)
- **直接放内容**,可用 blockquote `>` 标识引用
- 例: `> "运动解剖学是人体解剖学的一个分支..."` 而非 `讲义核心句:"运动解剖学是..."`

### 4. 口诀方法论(v2.7 新增,替换"押韵口诀"硬要求)

- **不限定押韵形式**——押韵只是记忆术之一,不是唯一
- **可用记忆术**:谐音、语意、首字连词、关键词、缩减、编歌诀、缩减排比
- **只为 4 个重点知识点服务**(其他知识点不强行配口诀):
  1. 核心定义/概念(如标准解剖学姿势)
  2. 大量易混项(如方位术语 8 对)
  3. 多维对比(如 3 轴 vs 3 面)
  4. 易错点串联

### 5. Obsidian 双链(v2.7 新增)

学习导航小节必须包含:
- **讲义来源**:`[[招教 体育 讲义库#章节锚点|讲义库·章节名]]`
- **背诵手册**:`[[背诵手册-{模块}#章节锚点|背诵手册·{模块}·章节名]]`
- **上一篇** / **下一篇**(预留)
- **本模块来源**:讲义库模块锚点

**锚点规则**(Obsidian 自动生成):`## 章节名` → `#章节-名`(空格→`-`,中文保留)

## 批量审核工作流（v1.3 新增）

> 老板说"审核某模块/某批讲稿"时触发。与"批量产出 SOP"平行（产出=从 0 写，审核=改既有稿）。

### 5 步成体系

**步骤 1：抽文件清单 + 跑 R1 自查（先看真实数据）**
- search_files / glob 拿目标目录所有 .md，统计篇数 + 字数
- 用 r1_self_check.py 一键过 R1-R6 + 结构 + 10 红线
- **不要拍脑袋估数字**——脚本说了算

**步骤 2：列每篇违规行号 + 类型分类**
- 自查脚本输出违规计数，但**看不到具体行号**
- 写小脚本（execute_code 或 terminal + 临时 .py）按行 grep 出每篇违规行号 + 原文 snippet
- 按 R1/R2/R5/R6/R7 分类聚合，给老板"反例模式分类表"

**步骤 4：出审核报告 + A/B/C/D 修订方案**

- A 选项默认是"批量 patch + 补缺漏"，给老板最稳的选择

**步骤 5：批量 patch → 二次验证 → 抽样核对**

- 二次跑 r1_self_check.py 验证 → **R1=0 不等于真合规**

## 长稿 write_file 截断陷阱（v2.6 新增）

**错的样子**：用 `write_file` 写一篇 1.5-2 万字的长稿——**写完后发现最后一两个模块（5/6/7）被截断**。

**根因**：write_file 工具在单次调用有**字符数上限**（实测 1.5-2 万字会触发）。长稿分两次写：先主体，再 patch 补"五、知识拓展/六、易错点拨/七、记忆口诀"。

**修法**：
- **预估字数**：用临时脚本算 +1500-2000 字符冗余
- **长稿拆 2 段写**：前 1-1.5 万字用 write_file，后面用 patch 补
- **写完立即自查字数 + R1**—— 不要等所有写完
- **写长稿前先 `$env:TEMP/` 落临时文件**，让 write_file 从临时文件读（**不适用于本任务**——临时文件还得 read_file 二次读）

## execute_code 沙箱超时陷阱（v2.6 新增）

**错的样子**：在 `execute_code` 里跑 Python 脚本，stdout 有 60+ KB 的 print 输出——`BLOCKED: execute_code script timed out without user response` 触发。

**根因**：execute_code 沙箱有 **5 分钟 timeout + 50 KB stdout cap**——长 print 撞 cap 后被强制中断，**但 user 不能响应 → BLOCKED**。

**修法**：
- **长 print 输出写到文件**（`f.write()`）→ read_file 分页读
- **拆小循环**：每次 print 10-20 条 + 计数器
- **不用 execute_code 跑长 print**——改用 search_files 单独抽行
- **本任务**（写稿+自查）execute_code 实际**用得不多**——主要用在 R1 re.sub 批量修复，**输出 < 1 KB，OK**

## 六维度横评机制（v3.6 新增）

> 用途：全库/模块批量审核讲稿时，对每篇（或抽样篇目）按 6 个维度 1/3/5 打分并加权计总，判断“合格/需小改/需返工”。命中六维横评任务时，完整读取 `references/六维横评机制_v1.md` 的细则与报告模板。

| 维度 | 权重 | 1 分 | 3 分 | 5 分 |
|------|------|------|------|------|
| ① 章节层级完整性 | 15% | 8 节缺失/层级错乱 | 齐全但个别子节薄弱 | 齐全且层级清晰 |
| ② 知识点覆盖与考纲契合 | 25% | 漏核心知识点/考频明显错误 | 基本覆盖但缺拓展或考频定位不准 | 全覆盖且定位准确 |
| ③ 举一反三迁移有效性 | 20% | 变式只换数字/主语 | 有递进但末组停在识记 | 识记→辨析→应用真迁移 |
| ④ 语言风格双场景适配 | 15% | 只有学生视角或术语过密 | 清晰但无讲授衔接 | 学生可自学且教师可照讲 |
| ⑤ 排版与可读性 | 10% | 长段堆叠/表格混乱 | 基本规范 | 层次/表格/引用/元信息齐全可直接汇编 |
| ⑥ 反例合规与红线 | 15% | R1 违规或红线词 | 0 违规但结构不达标 | R1=0 且结构全达标 |

**加权总分** = Σ(维度分 × 权重)，满分 5 分。**合格线：加权总分 ≥4.0 且无单项 1 分**；任一维度 1 分或总分 <4.0 → 需返工。

**全库批处理流程（5 步）**：
1. 自动全量扫描：r1_self_check.py + 8 节结构 + frontmatter + 题量题型 + 双链 + 考频（①⑥ 全量，②③④⑤ 出候选）；
2. 分层抽样深读：每模块 1-2 篇代表（全文或关键段落），②③④⑤ 打分；
3. 输出模块子报告：逐篇状态表 + 抽样六维表 + M 编号清单；
4. 输出总报告：全库六维统计 + 整体判定 + 条目化 M 意见；
