# 门禁栈与去 AI 味流水线（shared-gates）

答一道出厂前必须走完 10 步流水线（TR1 2026-11-20 答题线化：骨架/顺序/白熊隔离/CHECKPOINT/渲染契约沿裁定不变，查项与扫描对象按答一道口径改写；原技巧线 7+1 查项随技巧线退役删除，git 历史可找回）。

定稿沿革（Task6，2026-11-20；TR1 答题线适配）：
- 流水线顺序按君上裁定——**content_rules 跑在独立审稿+盲测之后，作最终出厂程序门禁**；
- check_prose 职责收窄为通用红线，虚构权威/模糊归因/来源不符归 content_rules（R14 及 pending/meta 校验），职责分界见「check_prose 程序红线与职责分界」节；
- 独立审稿查项含「动词+对象配对」通用项。

## 10 步流水线（答一道）

| 步 | 动作 | 契约 |
|---|---|---|
| 1 | 出题+读源+审题+草稿 | 三源选题（热点自出/真题库/模拟题库，题干 ≤80 字）；四源读源（讲义定源一本通对应章节）+ 审题五维 + 读源四要素；大纲区 7 字段+逐字稿 8 字段草稿按定调版口径写；draft_meta 按 `shared-sourcing.md` schema 落盘（pending），answer 扩展字段（审题五维记录/closing_type）必填；**题干确认弹窗在本步执行**（CHECKPOINT 第一处，见步 9） |
| 2 | humanizer-zh 诊断 agent（AI 模式清单扫描） | 契约见「humanizer-zh 诊断 agent 契约」节；扫描对象=大纲与解说段（逐字稿引文保真区不扫措辞），输出问题清单落盘；诊断 agent 只出清单不改稿 |
| 3 | humanizer-zh 改写 agent（另一会话/agent） | 契约见「humanizer-zh 改写 agent 契约」节；白熊隔离；只动措辞，不改答题结构，**逐字稿引文保真**；保留字段前缀 |
| 4 | check_prose.py 程序红线清零 | 用 skill 内副本 `scripts/check_prose.py`（human-writing v1.2.0+公考高危词叠加）；检查文本=改写后大纲/解说＋新写逐字稿 8 字段（引文保真区不进检查文本）；FAIL 项清零才过：公考高危词/破折号/翻案腔全族/否定式排比≤1/黑话/模型路标硬拦，冒号按字段前缀豁免，另按模板结构契约豁免结构性大纲提示行（整行以全角括号「（」开头、以「）」或「）：」收尾的 intro/标签行，行内冒号含行尾引导冒号不拦；判定限定整行形状，防正文句中冒号借机逃逸）；**不可用即 STOP 无降级** |
| 5 | 回核读源 | 改写稿对四源回核：术语/条件/方法含义不丢，审题五维的限制条件不被丢/改/加；教学事实源严禁改写 |
| 6 | 独立审稿（语义，换视角/评审代理） | 8 查项见「独立审稿查项（答一道 8 项）」节；review_conclusion 写"通过"才进盲测；任一查项不过回步 3 |
| 7 | 盲测试答出厂验收 | 按 `references/blind-test-protocol.md`：学生 persona 只读帖子全文（题目+思路大纲+逐字稿），独立产出新题完整定调版答题，判据四项全过 blind_test_result 写"通过"；未过回炉（回步 3 改写） |
| 8 | content_rules.py 出厂门禁 | `python3 scripts/content_rules.py --line answer --pending <pending_answer.json> --meta <draft_meta>`，**R0/R14 exit 0** 才进 CHECKPOINT；answer pending 校验与引擎 `render_cards.py` 的 `ANSWER_REQUIRED` / `core_views` 恰 3 条消费契约同表防漂移（docx/v3 引擎已归档，不再作为对表对象） |
| 9 | CHECKPOINT 用户弹窗（复核两处齐备） | 两处弹窗：①题干确认弹窗（步 1 执行，用户可"换一道"）②成稿前后对比 3-5 处弹窗（步 4 去 AI 味后执行）；本步复核两处弹窗记录齐备，**缺一不进渲染** |
| 10 | 引擎出稿 + 渲染近似检查 | draft 写入 final JSON → `python3 scripts/render_cards.py --mode answer --final <final JSON> --project-root <项目根> --outdir <期目录> --period-id <draft-id>`（v4 双模式：PIL 直出 6–8 张 1080×1440 PNG + 笔记文案.md；封面/思维导图/逐字稿自动分页/收尾引流/品牌页；只折行不截断、数字串不腰斩、缺字体 FAIL、outdir 越界 FAIL、尺寸异常 FAIL、渲染成功才追加 progress done，exit 0/1，机制见 `shared-engine-safety.md`，版式见 `references/DESIGN.md`）；渲染近似检查见「渲染近似检查」节；结论如实标注，**发布端复核才闭环** |

## humanizer-zh 诊断 agent 契约

- **触发**：humanizer-zh skill（读它的「编辑约束与优先级」「工作流程」「模式的使用方式」31 条）。
- **读取**：humanizer-zh `SKILL.md`（A–F 六类模式清单与边界说明），再通读草稿。
- **扫描对象（答一道口径）**：大纲区（破题角度/切入理由/核心观点）与解说性文字。**逐字稿 8 字段引自题库定调版时为教学事实源保真区——不扫措辞、不改一字**；热点自出题的新写逐字稿仍属诊断对象。
- **只拦 AI 腔，不拦答题体裁**：三段、第一/第二/第三、lead/body 是答题结构，不是 AI 痕迹；禁止建议把答案改成故事/叙事体。humanizer-zh 的模式是线索不是黑名单，没有问题的句子原样保留。
- **输出**：问题清单，每条 = 模式编号（如 A1/B6/C12）+ 原文引用 + 在答题语境里为什么是问题 + 修改方向（不写完整改写句）。按「表达问题 → 空泛铺垫 → 重复」排序，不按词表堆量。
- **落盘**：报告写入 vault `scripts/_draft_answer/`（文件名 `humanizer_diagnosis_<question_id>.md`），作为诊断与改写两 agent 之间**唯一交接物**，供改写 agent 读。
- **边界**：诊断 agent 只出清单不改稿；不产出改写稿、不读任何改写产物（白熊隔离）。
- **不可用即 STOP**：humanizer-zh 不可用时无降级，不跳过诊断。

## humanizer-zh 改写 agent 契约

- **输入**（仅此三样）：诊断清单 + 草稿（大纲/解说；新写逐字稿时含逐字稿草稿）+ 权威素材清单。
- **会话**：另起会话/新 agent 执行（白熊隔离）；不读诊断 agent 的任何草稿产物，只按清单定位。
- **事实与确定程度保真**（humanizer-zh 编辑约束 1）：不新增原文没有的事实、数字、名字、日期、经历、引文；不丢失独立信息；保留否定、比较对象、范围、条件、时间、完成状态与归因；不把相关改成因果、可能改成确定、计划改成已完成。
- **不改答题结构**：lead/body 分段、三点顺序、答题思路页的骨架不动；**禁止把分点答题改写成故事/叙事**。只改空泛铺垫、重复、含糊与模板腔。
- **逐字稿引文保真（答一道红线）**：引自题库定调版的逐字稿 8 字段一字不动；改写只落在大纲/解说措辞（新写逐字稿含措辞）。
- **保留字段前缀**：破题角度：/切入理由：/核心观点 等字段前缀（与 check_prose `TEMPLATE_PREFIXES` 同源），**只改冒号后正文措辞**。
- **经验注入**：权威素材为主（题库定调版逐字稿/教师注/方法论真实出处）；作者经历可选——用户供料时注入 1 个不可替换细节（标准：「换成别的例子不成立」）；**不冒充作者经历**；挖不到作者素材不阻塞。
- **humanizer-zh skill 不可用即 STOP 无降级**。

## 白熊隔离规则

诊断与改写**分两会话/agent**，禁止同会话串行。模式清单与坏例子进谁的工作记忆，谁就容易把它写出来。

| agent | 输入 | 输出 |
|---|---|---|
| humanizer-zh 诊断 agent | 大纲/解说（新写逐字稿含）、humanizer-zh SKILL.md 模式清单 | 问题清单（humanizer_diagnosis_<question_id>.md） |
| humanizer-zh 改写 agent | 问题清单、草稿、权威素材清单 | 改写稿 |

- 诊断 agent：只出清单；不产出改写稿、不读任何改写产物。
- 改写 agent：不读模式清单里的示例，只按清单定位。
- 两 agent 均不得改 humanizer-zh skill 文件（只读）；均不得改动逐字稿引文保真区。

## 独立审稿查项（答一道 8 项）

换视角/评审代理执行，语义判。8 项（⑧ 为 +1 通用查项）：

1. **来源微标兑现**（v3 图卡口径）：`source` 与 `title_prefix` 匹配（真题库=`结构化历年考题：`，自出/模拟题库=`结构化每日一练：`），卡 02 微标随之显示「历年考题」/「每日一练」，引擎 `validate_final` 已强制校验；题干原文完整上卡（卡 02）；题干设问/争点在正文逐项有回应。
2. **审题五维齐且限制条件不丢改加**：draft_meta 审题五维记录五项（设问/身份/对象/限制条件/主要争点）齐全；逐字稿对题干给定事实与前提不丢、不改、不加；每个主要争点有对应段。
3. **大纲三观点定调版口径**：三观点呈现分析关系（递进/并列/时间轴按题型），不为凑三点灌水；观点与正文三个 point 块一一对应，改稿两边一致。
4. **逐字稿口径合规**：唯一口径 opening 至 closing 汉字数（不含标点）700–800、硬边界 680–820；8 字段结构完整；开场破题定调+开篇三禁（不编题干外事件/不场景故事开头/不先讲经历）；收尾落在判据式/总结式且与 draft_meta closing_type 一致（口径见 `shared-calibration.md`）。
5. **逐字稿忠实度**：逐字稿引自题库定调版时与 `quote_excerpts` 回核**逐字一致**（教学事实源）；引用性表述不得升级为断言，条件不得删改。
6. **AI 味终判（词汇/句式/结构/经验层）**：套话/AI 高频词清零、无导游式路标与硬落金句、无匀速句长与否定排比堆叠、无编造细节冒充经历；humanizer-zh 诊断清单中的表达问题已处理，且**答题结构未被改写成故事/叙事**。
7. **盲测判据与协议一致**：本轮盲测安排与 `blind-test-protocol.md` 一致——输入仅帖子全文+新题题干（白盒禁令生效）、新题由主持方另选同题型未用题、判据四项逐项留档。
8. **（+1）动词+对象配对**：措施/动作表述含具体动词+对象、可直接照做；无"加强/完善"类无对象空动作。

review_conclusion 写"通过"才进盲测；任一查项不过回步 3 改写。

## 审稿与盲测操作流程

两道门的评审代理 dispatch 指引；查项与门禁顺序仍以上文为准，本节只补操作流程。

**区别与互替禁令**：审稿可读源核忠实度/方法含义，盲测只读帖子核"能照做"；**两者独立不可互替**——审稿通过≠盲测通过，盲测通过≠审稿通过，任一门不过都回步 3 改写。

### 独立审稿操作流程（步 6）

- 评审代理另起会话/新 agent（换视角），**不带写稿记忆**。
- **输入**：帖子全文（题目+大纲+逐字稿）＋draft_meta 读源记录＋源材料只读权限——审稿允许读源，用于核忠实度与查项 2/3/5。
- 按「独立审稿查项（答一道 8 项）」逐项裁决，每项给证据（锚定帖子原文/源材料原句）。
- **输出**：review_detail（8 项逐项：查项/证据/结论）＋review_conclusion 写入 draft_meta；`review_conclusion=="通过"` 才放行进盲测，任一查项不过回步 3 改写。

### 盲测操作流程（步 7）

- 评审 agent **输入仅两项**：帖子全文＋新题题干。**白盒禁令：禁读源材料/方法论/题库/教师注/draft_meta 读源记录**（盲＝只读读者能看到的东西）；已读过源材料的会话不得执行盲测。
- persona/任务/判据按 `references/blind-test-protocol.md` 执行（本文件不复制其内容，防两处漂移）。
- **输出**：blind_test_detail（判据逐项留档）＋blind_test_result 写入 draft_meta；`blind_test_result=="通过"` 才进步 8；未过回炉（回步 3，轮次证据留档）。
- **集成契约**：盲测新题从题库另选**同题型未用题**（非本期 src 题），由主持方（主对话）提供，评审 agent 不自选题。

## CHECKPOINT 用户弹窗（两处）

1. **题干确认弹窗**：步 1 出题/选题后弹（选项如"OK，继续"/"换一道"，不让用户打字）；用户选"换一道"回步 1 重出题/重选题。
2. **成稿前后对比 3-5 处弹窗**：步 4 去 AI 味后弹，改写前后对照给用户过目。

步 9 复核两处弹窗记录齐备，缺一不进渲染。

## check_prose 程序红线与职责分界

- **副本**：skill 内 `scripts/check_prose.py`。来源 = human-writing v1.2.0 `scripts/check_prose.py`，收录日期 2026-11-20，上游更新**手动同步**非自动；叠加公考高危词表 12 词（出现即 FAIL 报"公考高危词"），human-writing 原文检测逻辑不动；TR1 扩充答一道字段前缀（切入理由/核心观点）进 `TEMPLATE_PREFIXES`（既有"新栏目前缀两处同步扩充"契约的执行）。
- **检查文本（答一道口径）**：改写后大纲/解说＋新写逐字稿 8 字段；**逐字稿引文保真区不进检查文本**。
- **通用红线（check_prose 管）**：破折号/翻案腔全族/冒号（字段前缀豁免＋结构性大纲提示行豁免：整行「（…）」/「（…）：」形状）/否定式排比≤1/黑话/洞察路标词/公考高危词。
- **content_rules 管**：R0 读源记录、R14 审稿记录完整+两结论=="通过"、pending 与引擎消费契约同表校验（步 8 全量门）。
- **多道门不冗余**：两门职责如上分界，互不重复；改 check_prose 词表不改 content_rules 检测逻辑，反之亦然。
- **不可用即 STOP 无降级**：check_prose 不可用时不允许跳过程序红线直接交稿。

## 渲染近似检查

**v4 图片产线（现行）**：产物是 5–8 张 1080×1440 PNG，不再是 docx，所以不再需要 `textutil` + 无头 Chrome 的 docx 近似渲染。现行检查分两级：

1. **程序级**（必过，exit 0 才算过）：`render_cards.py` 自带 `--check` 数据校验（字段/档位/真题前缀）＋ 每张图 1080×1440 尺寸断言 ＋ outdir 边界校验。全 PASS 且渲染成功才追加 progress done。
2. **目检级**（必做，人眼/读图）：逐张看全部 PNG，按 `references/DESIGN.md` §10 验收清单核：封面层级、页眉页脚对齐、水印不压字、导图不穿字、CTA 只出现一次、品牌页完整、张数在范围内。

结论如实标注两级："程序通过"（引擎自检 + `--check`）/ "发布端通过"（小红书发布端实况）。**发布端复核才闭环**，程序通过不算终态。

> 归档参考（docx 时代，已不执行）：375px 手机宽度 textutil + 无头 Chrome 近似渲染 docx 产物。

## 经验注入适配教学帖

humanizer-zh 改写适配教学帖：教学帖"真实"＝权威可核验出处（题库定调版逐字稿/教师注/方法论真实出处）为主，作者经历可选（用户供料时注入 1 个不可替换细节）；"绝不编造作者经历"铁律保留；挖不到作者素材不阻塞。答一道逐字稿引文保真区不参与经验注入（一字不动）。humanizer-zh 只改表达，不改答题结构与事实强度。
