## 电车站诊断 agent 契约

- **触发**：tramstop-skill 模式一（诊断）。
- **读取**：tramstop `references/checklist.md`（分层特征清单），再通读草稿。
- **扫描**：按四层扫描——词汇层/句式层/结构层/经验层，每个发现**引用原文位置**。
- **输出**：分层报告，按权重排序 **经验层 ≥ 结构层 > 句式层 > 词汇层**；报告回答三问：
  1. 这篇稿子的细节里，有几个是"换成别的例子也成立"的？
  2. 判断有没有押注？还是全在两头堵？
  3. 删掉所有修辞后，剩下的信息量撑得起这篇文章吗？
- **落盘**：报告写入 vault `scripts/_draft_tips/tramstop_diagnosis.md`，作为诊断与改写两 agent 之间**唯一交接物**，供改写 agent 读。
- **边界**：诊断 agent 只出报告不改稿；不产出改写稿、不读任何改写产物（白熊隔离）。
- **不可用即 STOP**：tramstop-skill 不可用时无降级，不跳过诊断。

## human-writing 改写 agent 契约

- **输入**（仅此三样）：诊断报告（tramstop_diagnosis.md）+ 草稿 + 权威素材清单（D23）。
- **会话**：另起会话/新 agent 执行（白熊隔离）；**不读 tramstop references/checklist.md 坏例子清单**，只按诊断报告定位的结构层/经验层病灶改写。
- **词层分工**：词层红线不由改写 agent 自查兜底，由 check_prose 程序兜底（步 4）。
- **经验注入（D23）**：权威素材为主（题库定调版逐字稿/教师注/方法论真实出处）；作者经历可选——用户供料时注入 1 个不可替换细节（电车站标准："换成别的例子不成立"）；示范标"示范"不冒充作者经历；挖不到作者素材不阻塞。
- **保留模板前缀**：适用题型：/第一步：/普通答法：/点评：/避坑提醒：等——清单按 C1 字段职责派生（与 check_prose `TEMPLATE_PREFIXES` 同源，新栏目前缀两处同步扩充），保留字段前缀契约。human-writing 冒号禁令与字段前缀的边界冲突按"前缀豁免"处理保留：**只改冒号后正文措辞**。
- **保留**：hashtag 内容与数量（5-8 个，固定 #公考面试 #结构化面试 #上岸）、emoji 摆位。
- **翻案腔清零**：不是…而是/并非…而是/不在于…而在于/与其说…不如说/看似…实则全族，在正文措辞层清零。
- **不冒充作者经历**；**电车站/human-writing skill 不可用即 STOP 无降级**。

## 白熊隔离规则

诊断与改写**分两会话/agent**，禁止同会话串行。坏例子清单进谁的工作记忆，谁就容易把它写出来。

| agent | 输入 | 输出 |
|---|---|---|
| 电车站诊断 agent | 草稿、tramstop `references/checklist.md` | 分层报告（tramstop_diagnosis.md） |
| human-writing 改写 agent | 分层报告、草稿、权威素材清单 | 改写稿 |

- 诊断 agent：只出报告；不产出改写稿、不读任何改写产物。
- 改写 agent：不读 checklist.md 坏例子清单。
- 两 agent 均不得改 tramstop/human-writing skill 文件（只读）。

## 独立审稿查项（定稿，7+1）

换视角/评审代理执行，语义判。7 项：

1. **标题兑现**：正文兑现 tip_title 承诺。
2. **点评有据**：批评逐句锚定 case_normal 原话；区分"没有说明 X"与"说错了 X"。
3. **方法含义**：边界内关键条件不丢+可照做——**动词+对象配对**、问句/动作模板可直接照做。
4. **边界**：适用/不适用/教师注齐（教师注条件性条目被 boundary_evidence 吸收）。
5. **练习可作答**：新场景所需知识正文已讲清。
6. **认知增量**：每期一个"原来想错了/不知道"的点，cognitive_gain 非空且具体。
7. **示范定调版口径符合**：opening 破题定调+body 段、三禁、demo_source 标明。

+1 通用查项：**动词+对象配对**（Task5 reviewer 建议，防程序与审稿互相以为对方在查——R11 程序只查动作动词线索，审稿查"问句/动作模板可直接照做"的语义，含动词+对象配对）。

review_conclusion 写"通过"才进盲测；任一查项不过回步 3 改写。

## 审稿与盲测操作流程（Task8 补充）

两道门的评审代理 dispatch 指引；查项与门禁顺序仍以上文定稿为准，本节只补操作流程。

**区别与互替禁令**：审稿可读源核忠实度/方法含义，盲测只读帖子核"能照做"；**两者独立不可互替**——审稿通过≠盲测通过，盲测通过≠审稿通过，任一门不过都回步 3 改写。

### 独立审稿操作流程（步 6）

- 评审代理另起会话/新 agent（换视角），**不带写稿记忆**。
- **输入**：帖子 15 字段全文＋draft_meta 读源记录＋源材料只读权限——审稿允许读源，用于核忠实度与「方法含义」查项。
- 按「独立审稿查项（定稿，7+1）」逐项裁决，每项给证据（锚定帖子原文/源材料原句）。
- **输出**：review_detail（7+1 逐项：查项/证据/结论）＋review_conclusion 写入 draft_meta；`review_conclusion=="通过"` 才放行进盲测，任一查项不过回步 3 改写。

### 盲测操作流程（步 7）

- 评审 agent **输入仅两项**：帖子全文＋新题题干。**白盒禁令：禁读源材料/方法论/题库/教师注/draft_meta 读源记录**（盲＝只读读者能看到的东西）；已读过源材料的会话不得执行盲测。此为 D8 出厂门禁盲测性核心。
- persona/任务/判据按 `references/blind-test-protocol.md` 执行（本文件不复制其内容，防两处漂移）。
- **输出**：blind_test_detail（判据逐项留档）＋blind_test_result 写入 draft_meta；`blind_test_result=="通过"` 才进步 8；未过回炉（回步 3，轮次证据留档）。
- **集成契约**：盲测新题从题库另选**同题型未用题**（非本期 src 题），由主持方（主对话）提供，评审 agent 不自选题。

## 盲测试答

引用 `references/blind-test-protocol.md`（Task8 填充；本文件定稿时为 stub，**不在此复制其内容**，防两处漂移）。判据通过后 blind_test_result 写"通过"；未过回炉。

## CHECKPOINT 用户弹窗（两处，D20）

1. **选题 2-3 候选弹窗**：步 1 选题时弹，用户挑选后进草稿。
2. **成稿前后对比 3-5 处弹窗**：步 4 去 AI 味后弹，改写前后对照给用户过目。

步 9 复核两处弹窗记录齐备，缺一不进渲染。

## check_prose 程序红线与职责分界

- **副本**：skill 内 `scripts/check_prose.py`。来源 = human-writing v1.2.0 `scripts/check_prose.py`，收录日期 2026-11-20，上游更新**手动同步**非自动；叠加公考高危词表 12 词（体现/彰显/凸显/深入推进/全面落实/持续优化/多措并举/综合施策/协同推进/切实保障/有效提升/有力推动，出现即 FAIL 报"公考高危词"），human-writing 原文检测逻辑不动。
- **通用红线（check_prose 管）**：破折号/翻案腔全族/冒号（字段前缀豁免，见改写契约）/否定式排比≤1/三段式凑数（程序强警告，语义终判归独立审稿）/黑话/洞察路标词/公考高危词。
- **content_rules 管**：R7 在步 8 全量门拦"虚构权威/模糊归因/来源不符"。
- **多道门不冗余**：两门职责如上分界，互不重复；改 check_prose 词表不改 content_rules 检测逻辑，反之亦然。
- **不可用即 STOP 无降级**：check_prose 不可用时取消 tips 现行 fallback，不允许跳过程序红线直接交稿。
