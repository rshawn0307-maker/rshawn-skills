# 内容味道契约（content-voice）

> 适用：structured-daily 双模式（answer / tips）。这是「反程序化」的唯一内容事实源。
> 程序门禁：`scripts/check_voice.py`（R1–R7）；措辞门禁：`scripts/check_prose.py`。

## 0. 先认清问题：读者说的「程序化」是什么

对 2026-04/05 高数据帖（#2 3080 赞、#67 3217 赞、展开说说 2871 赞）与 2026-09/11 低数据帖（#180 38 赞）逐页对照后，结论不是「近期用词更 AI」——近期稿的禁词和句长反而更干净。真正掉下去的是三件事：

1. **框架密度**：早期 #2 的导图页有 5 大分支、12 个以上具体点，评论夸「全面、实用」；近期稿没有导图，只剩 3 句核心观点，读者拿不到可复用的骨架。
2. **推进方式单一**：近期 body 常写成「第一步…第二步…第三步…」，每步一句标签 + 一段解释；早期 #67 用设问推进（「蝴蝶为什么吹不走？因为它有生命」），有论证、有对比。
3. **缺取舍与现场细节**：近期 opening 多是正确但无棱角的判断，point body 缺「谁、多久、怎么说」的可核查动作；读者感觉像评分手册，不像一个干过活的人在答题。

一句话：**AI 味不是词，是「均衡、无取舍、无细节、结构外显」**。强模型默认就给这种答案，所以模型越强、越要把它按住。

## 1. 六条底色（沿用 2026-04 起的教研口径，不可妥协）

答题不是写作文，是「考场口述」。

1. **有观点**：第一段就定调，敢说「我认为」「本质是」「核心矛盾是」；不写「客观来说」「值得我们思考」。
2. **有逻辑**：每段有「承上→启下→落到点」的内部节奏，三段不是孤立的三个块。
3. **有表达**：节奏有快有慢，长短句交替；不靠「第一/第二/第三」机械推进。
4. **不套路**：不写「领导让我干这个」这类万能套话。
5. **不假大空**：不写「体现了…彰显了…标志着…」注水标语。
6. **接地气**：观点落到具体抓手（数字、时限、角色、动作），不说虚的。

## 2. 反程序化五条（v4.1 新增，硬线）

1. **框架先给全**（answer）：`mindmap` 必填，≥4 分支、≥12 叶子；叶子写具体抓手（「1 个工作日签收」「逐家电话回访」），不写抽象名词（「提升意识」「完善机制」）。
2. **开篇必须有取舍**：opening 写成「必须先 X 后 Y，因为…」「关键不在 A，在 B」这类判断；只复述题干或只表态「要重视」不算。
3. **三点不同推进**：三条 lead 不得同一种开头；「我」开头最多 1 条；「第 X 步」全篇最多 1 次。可用「先…再…最后…」「表面…其实…所以…」「为什么…因为…怎么办…」三种推进轮换。
4. **每点至少 2 个现场细节**（answer）：数字＋单位、具体角色（商家/窗口/社区/领导/当事人）、具体动作（走访/登记/回访/广播/公示）三者合计 ≥2。tips 线：AIR 整档 ≥1，Pro / Pro Max 每点 ≥1。
5. **全篇至少 1 处边界**：说清这招什么时候不适用（「如果题干问的是如何看待，就先讲意义再讲做法」「遇到已造成伤害的题，两面压短」）。

## 3. 内容源优先级（防止空对空）

| 优先级 | 来源 | 要求 |
|---|---|---|
| 1 | 真题库 / 模拟题库定调版 | 逐字保真；不改教学事实源 |
| 2 | 讲义 + 一本通对应章节 | 先读源再写；术语与条件不得自造 |
| 3 | 热点自出题 | **先写事实卡**：3 个可核查事实（发布主体/时间/数字/原文表述），再写稿；写不出事实卡就换题库题 |

热点自出题的事实卡写进 draft_meta 的 `fact_card`，没有事实卡的稿子不进渲染。

## 4. 正面样例（摘自 4–5 月高数据帖，学结构不抄内容）

- 开篇定调（#67）：「风是一样的风，白纸和蝴蝶也是同样的重量，但结局截然相反——白纸被吹走，蝴蝶却逆风而飞。区别在哪？白纸没有自己的方向，蝴蝶有。」——先给对比，再给判断，再引出论点。
- 设问推进（#67 主体）：「白纸之所以被吹走，不是风太大，而是它太'空'。……蝴蝶为什么吹不走？因为它有生命，生命就有方向。」——每一块用问题领着走，不是标签。
- 框架密度（#2 导图）：开篇总述 / 积极意义 / 现存隐患 / 解决对策 / 结尾总结，五个分支各 2–3 个具体点，读者一眼拿走骨架。
- 收尾（#67）：「总之，同样的风，吹走白纸，吹不走蝴蝶。区别不在重量，而在生命力。」——回扣比喻，一句判断收束，不是「综上所述」。

## 5. 门禁与命令

```bash
python3 scripts/check_voice.py --mode answer --final <final.json>
python3 scripts/check_voice.py --mode tips   --final <final.json>
python3 scripts/check_prose.py <检查文本文件>
```

- `check_voice` 的 FAIL 必须清零；WARN（句长、边界、短句占比）人工判断后处理。
- `check_prose` 仍按原口径：硬禁词清零；tips 检查文本用「。」连接 lead 与 body，不用「：」。

## 6. 防过度修改

- 正常的三项列举（「A、B、C」）不改；只有全文每段都同构三连时才调节奏。
- 不为过门禁删掉有效信息；先补具体细节，再删空话。
- 不把「答题完毕」「以上就是我的回答」当 AI 标记——早期高数据帖同样使用，是否保留由口播习惯决定。
