# 结构化每日一练·自动化帖子生成

## 适用场景

用户要做"公务员结构化面试·每日一练"系列小红书/公众号帖子，需要：
1. 出题 + 审题 + 答题（结构化面试，总分总，正文 800—1000 字，去 AI 味儿后）
2. 自动套入固定 docx 模板（含配图 + 引流文案）
3. 保留模板所有版式（封面文本框、分页符、引流段样式）

## 工作流（出题 → 审题 → 答题 → 去AI味儿 → 内容复核 → 套版式 → 上传，一步不跳）

### 步骤 1：自出题

要求：
- **题干必须 ≤80 字（硬上限）**——踩坑后立的规矩；超过 80 字阅读节奏断档、热点反差感丢失
- **选题优先从近期热点且适合结构化题目的话题着手**：先搜近期新闻/政策/社会现象，挑有矛盾张力、能多角度展开的题材；避免过于专业的岗位题
- 热点话题、政策类、社会现象为首选题材
- 避免过于专业的岗位题；用户指定岗位时按指定岗位出题
- **写完题干先 `len(question)` 自检**，**超就砍**，**别等用户指出**

**🔴 CHECKPOINT · STOP**：题干确认 → 用 `AskUserQuestion` 弹窗选项让用户确认（选项如："OK，继续"、"换一道"），**不要让用户打字**。用户选"换一道"→ 回到本步骤重出题。

### 步骤 1.5：审题 + 读方法论（写大纲前必做，🔴 本 skill 与"随手写一篇"的分水岭）

题目确认后**不要直接写大纲**。先做两件事，结论写给自己看（不进正文），但要落实到大纲和正文里。

**① 审题**——从题干逐项识别：

| 维度 | 要识别什么 |
|------|-----------|
| **设问** | 问的到底是什么（怎么看 / 怎么办 / 怎么组织 / 怎么沟通）？有没有"重点针对XX""你会怎么处理"这类限定？ |
| **身份** | 我在题里是谁（考生 / 事件当事人 / 某岗位工作人员）？权限边界在哪，哪些事不归我管？ |
| **对象** | 对谁说话、处理谁的什么诉求？多方诉求要逐一列出 |
| **限制条件** | 题干给定的事实与前提（资源、时间、已发生的事、矛盾现状）——正文不能丢、不能改、不能加 |
| **主要争点** | 这道题真正拉开差距的 1—2 个关键问题（如"程序正义 vs 名誉恢复""经营诉求 vs 居住安宁"）——正文优先答透的就是它们 |

**② 读对应方法论**——按题型读 `<方法论根>/各题型方法论/<题型>题_方法论提炼.md`（如综合分析读 `综合分析题_方法论提炼.md`），需要例题参照时再看 `<方法论根>/答题框架模板/答题框架模板_六大题型提炼.md` 和 `<方法论根>/讲义/` 对应章节。读完从中**选出本题适用的 3—5 项要求**带进写作，并想清楚每项为什么适用于这道题——不是证明"读过文件"。

**方法论取舍规则（重要，防止被带偏）**：
- 方法论是从样稿提炼的，里面的金句、排比、数字、场景是**可选技巧**：用不用、用几处，服从本题论证需要。文件里凡"每篇至少X个金句/排比/数字/场景"的频次要求，**一律不作硬性要求**
- 四项优先标准：**依据充分、推理成立、措施针对、表达清楚**——所有技巧服从这四项，冲突时砍技巧保论证
- 方法论里的示范句式、人物、数字在题干没有支持时，**不得当作事实材料或本人经历搬用**（"似真实"的引语也不能当事实写）

### 步骤 2：写大纲 + 答题初稿

把步骤 1.5 的审题结论落成大纲，再往正文承载块里装内容。**先组织逻辑，再写文字**。

#### 大纲要求（大纲是教学件，不是答案摘要）

- **破题角度**后用一句话说明**为什么从这个角度切入**：题干哪个信息、哪个争点决定的。让学员学到的是"换一道题怎么找角度"，不是背结论
- 三个核心观点要呈现**分析关系**（递进 / 并列 / 按时间轴），让读者看得出观点从哪来
- **不为凑三点灌水**：模板固定 3 个观点位，若素材只够两个实质角度，回步骤 1.5 换角度或换展开结构，而不是把第三个观点写成注水段
- 观点与正文三个 point 块一一对应；改稿先改大纲再改正文，两边保持一致

#### 正文承载与篇幅口径

- 正文承载块固定：opening → 第一/第二/第三（lead + body）→ closing
- **篇幅唯一口径：正文 = opening 至 closing 全部文字（含标点），不含题干与大纲，目标 800—1000 字**
- 低于 800 字先补论证和措施的适用条件，不是补套话；逼近 1000 字优先砍次要措施
- **不承诺口述时长**：没有录音实测就不报告"X 分钟内能答完"，最多按字数折算并注明是估算

#### 核心观点展开方式（按题型选择，写大纲时定）

| 展开方式 | 适用题型 | 结构 |
|----------|---------|------|
| **3 观点结构** | 综合分析/自我认知/言语表达 | 3 个并列观点，每个有论据+论点 |
| **时间线结构** | 组织计划/应急应变 | 事前准备 -> 事中执行 -> 事后复盘 |
| **多维分析结构** | 综合分析政策类 | 个人层面 -> 社会层面 -> 政府/制度层面 |

选题后根据题型自动匹配展开方式，不要所有题都套"3 观点"。

#### 论证规则（综合分析从严，其余五类保底）

**综合分析按子题型**：
- **社会现象题**：解释现象**怎么形成、靠什么持续**（从激励结构、成本收益、信息差、监管难度等机制里挑本题最相关的说透），不能停在"这种现象不好"
- **政策理解题**：解释政策**作用路径**（改变了谁的成本/收益/行为，怎么传导到目标问题）和**实施条件**（钱、人、权责、配套），不能从"方向正确"直接跳到"问题已经解决/历史任务完成"这类大结论
- **观点理解题**：先解释观点的**含义和适用边界**（什么条件下成立、何时失效），再表态；不做单因归因，不下比论证走得更远的断言

**综合分析通用**：
- 核心判断要有题干事实、公认事实或完整推理链支撑；单个间接证据（如一处交易量数据）推不出制度性结论时，补齐中间环节或收窄结论
- **每条关键措施要能回答"它解决前面分析的哪个问题"**——对不上的措施砍掉或降为补充
- 一段话删掉题干关键词后仍能原样套进大量同类题，说明是模板段，重写

**其余五类（最低要求，细则读各自方法论）**：

| 题型 | 最低要求 |
|------|---------|
| 组织计划 | 明确对象、实施难点、资源条件和效果判断 |
| 人际关系 | 区分事实与猜测，沟通服务于解决工作问题，保留原则边界 |
| 应急应变 | 按紧迫程度安排动作，明确条件分支和本人权限 |
| 自我认知 | 用真实经历体现个人选择、行动与改变；**没有用户提供的材料时不冒写亲历** |
| 言语表达 | 直接进入角色，回应对象顾虑，不写成"我将如何沟通"的说明稿 |

#### 内容风格铁律（必须满足）

答题不是写作文，是"考场口述"。要的是高分感，不是字数堆砌。**6 条不可妥协**：

1. **有观点**——敢说"我认为""本质是""核心矛盾是"，别用"客观来说""值得我们思考"这种和稀泥
2. **有逻辑**——每段要有"承上 → 启下 → 落到点"的内部节奏，别三段孤立
3. **有表达**——节奏有快有慢，长短句交替；避免每段都"第一""第二""第三"机械
4. **避免套路**——不写"领导让我干这个、领导让我想这个"那种万能套话
5. **拒绝假大空**——不写"体现了……彰显了……标志着……"那种注水标语
6. **有深度、可操作、接地气**——观点要落到具体抓手（数据、案例、动作），不说虚的

**白话原则**：写完大声读一遍——读起来像"人话"再继续，读起来像"作文"就重写。


### 分题型高分要素差异化

不同题型考官看的核心不同，逐字稿侧重点要跟着变：

| 题型 | 考官最看重的 | 逐字稿侧重点 | 常见失分点 |
|------|------------|-------------|-----------|
| **综合分析** | 分析深度，透过现象看本质 | 重"本质+机制+对策"递进，观点要有判断力 | 停在现象层，缺机制分析 |
| **组织计划** | 流程完整性 + 可落地性 | 按"事前准备/事中执行/事后复盘"时间线展开，对策要有具体抓手 | 万能模板"领导交给我"，缺细节 |
| **人际关系** | 情商 + 原则性平衡 | 重"情理法"平衡：先理解对方 -> 再分析矛盾点 -> 给出兼顾方案 | 一味忍让或一味对抗 |
| **应急应变** | 轻重缓急排序 + 快速反应 | 按"止损/调查/处置/善后"优先级展开，先解决最紧急的 | 平均用力，没排序 |
| **自我认知** | 真实性 + 岗位匹配度 | 用具体经历支撑观点，不说空话"我很努力" | 假大空自我表扬 |
| **言语表达** | 感染力 + 对象感 | 有"对人说话"的对象感，不是背稿，注意语气身份适配 | 背演讲稿腔调 |
#### 公考面试用语禁忌（避免踩雷）

公考面试是正式场合，**用语得体、政治正确、考官听得进**——是比"有观点"更基础的红线。**4 类不要写**：

1. **不要带贬义色彩的比喻词**：落水狗、狼狈、龟孙、痛打、狼狈为奸等
2. **慎用网络流行词**：韭菜、小白、键盘侠、内卷、摆烂、躺平、yyds、绝绝子等
3. **慎用情绪化表达**：气死、笑死、巨坑、血亏、无语、离谱等
4. **不要有政治风险**："上面""领导拍脑袋""上面不作为"等不指明的吐槽；涉及民族、宗教、性别等要中性得体

**白名单替换原则**：
- 想用比喻 → 改成中性描述（如"落水狗"→"整治覆盖得了的只是显性摊位"）
- 想用网络词 → 改成书面表达（如"内卷"→"过度竞争"、"躺平"→"消极应对"）
- 想吐槽 → 改成建言（"运动式执法难持续"已经是建言式吐槽，OK）

**自检**：写完最后一遍**"考官读出来不得罪人"**——能过即可继续；任何一句读出来让考官皱眉或"笑场"，重写。

### 步骤 2.5：去 AI 味儿（必跑，套用 human-writing）

**写完初稿 → 必跑 human-writing → 过步骤 2.6 内容复核 → 才能进 pending_answer.json**。这是硬步骤。

操作：
`
触发 human-writing skill，对 8 个答题字段逐个 / 合并重写
`

重点扫（以 human-writing 现行硬禁令为准，只处理禁令命中的句子）：
- "标志着""彰显了""体现了""不断演变的"等 AI 标志性短语
- 破折号清零（"——"一律改逗号或句号，human-writing 硬禁令）
- 中文/英文冒号清零（引出人物直接原话、网址、代码与机器字段除外）
- 模糊归因（"专家认为""业内人士表示"）
- 否定式排比与翻案腔（"这不仅仅是……而是……""不只……还……""表面……实际……""说到底"等，human-writing 已禁）

**两条防过度修改的纪律**：
- **正常的三项列举不改**。"A、B、C"是自然的中文列举，只有当全文段落节奏机械雷同（每段都是同构三连）时才调整节奏，且不许因此增删内容
- **不强制固定收尾词**：收尾如果只剩模板腔（"总之/综上所述"开头、后面没有新信息），重写成有内容的收束；收束用什么词由内容决定，不用"说到底"（禁）

**写完 human-writing 版后自检**：
- 总字数按步骤 2 唯一口径（opening 至 closing，含标点）仍在 **800—1000**
- 读起来像人话（用 human-writing 的 scripts/check_prose.py 检查，同仓库安装时位于 `../human-writing/scripts/check_prose.py`；冒号/破折号/翻案腔按 human-writing 最新版硬禁令，全部清零）

详细规则参见 human-writing skill 的 SKILL.md（同仓库安装时位于 `../human-writing/SKILL.md`；若在其他位置则以实际安装路径为准）。

**优先路径**：直接触发 human-writing skill 对 8 个答题字段逐个/合并重写。

**降级触发条件**（仅以下情况走降级）：
- skill 调用报错 / 输出为空 / 输出未包含任何改写
- 此时按以下 5 条内联规则手动检查并重写：
1. **删 AI 标志性短语**：搜索"标志着""彰显了""体现了""不断演变的""发挥了重要作用"→ 删除或改写为具体动作
2. **清破折号和冒号**：搜索"——""："与":" → 全部改逗号或句号（引出人物直接原话、网址、代码与机器字段除外）
3. **改模糊归因**：搜索"专家认为""业内人士表示""有观点认为"→ 改为具体来源或删除
4. **破否定式排比**：搜索"这不仅仅是……而是……""说到底"→ 改为直述句，判断从正面下
5. **重写空收束**：收尾只有"总之/综上所述"+空话时，改为有内容的收束（具体行动或价值落点），不强制固定开头词

**降级自检**：写完读一遍，读起来像"考场口述"而非"AI 生成文"——能过即可继续。
**降级标注**：在 pending_answer.json 同目录写一个 `human-writing_fallback.txt`，内容"human-writing unavailable, used inline rules"，让后续审阅者知道走的是降级路径。

### 步骤 2.6：改写后内容复核（必过，防"改写丢内容"）

去 AI 味儿是文字手术，可能顺手切掉论证。拿改写稿对照初稿逐项核对，**五项全过才进步骤 3**：

1. **事实与出处**：改写稿没有新增初稿没有的事实、数字、引语；引用性表述没有被升级为断言
2. **观点强度**：结论没有被放大——"有助于降低X"不能变成"X从此解决"，有条件的判断不能变成绝对断言
3. **因果链**：初稿的机制解释（为什么 → 怎么传导 → 所以）在改写稿里仍然完整，没有被压缩成口号
4. **动作与限制条件**：措施的适用范围、实施主体、"先A后B"的顺序没有被删改
5. **设问回应**：步骤 1.5 列出的每个主要设问/争点，在改写稿里仍有对应段落

任何一项不过：回到该句，先恢复它原本要表达的事实，再按 human-writing 规则重新表述——不是机械回滚，也不为凑禁令清零而牺牲内容。**改后只有换词变化、没有内容改善，不认定复核通过。**

**🔴 CHECKPOINT · STOP**：去AI味儿 + 内容复核确认 → 把 humanize 前后对比的关键改写点（3-5 处）和复核五项结论展示给用户，用 `AskUserQuestion` 弹窗选项让用户确认（选项如："够自然，继续"、"还是像AI，再调"），**不要让用户打字**。用户选"还是像AI"→ 重跑 human-writing 或手动调整，并重走步骤 2.6。
