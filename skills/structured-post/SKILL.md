# 结构化每日一练·自动化帖子生成

## 适用场景

用户要做"公务员结构化面试·每日一练"系列小红书/公众号帖子，需要：
1. 出题 + 审题 + 答题（结构化面试，总分总，正文 700—800 汉字（不含标点），硬边界 680—820，电车站去 AI 味儿后）
2. 自动套入固定 docx 模板（含配图 + 引流文案）
3. 保留模板所有版式（封面文本框、分页符、引流段样式）

## 工作流（出题 → 审题 → 答题 → 电车站诊断 → 电车站改写 → human-writing 门禁 → 内容复核 → 套版式 → 上传，一步不跳）

### 步骤 1：出题（自出题、真题库选题或模拟题库选题）

**题目来源三选一**：

| 题目来源 | 做法 | JSON 标记 |
|------|------|------------------------------|
| 热点自出题 | 按下方要求新出题 | `title_prefix` 可省略（默认「结构化每日一练：」） |
| **真题库选题** | 从 `<真题库根>` 挑一道，题干照录，用户确认后作答；**不**再自出题 | **`"source": "真题库"` + `"title_prefix": "结构化历年考题："`** |
| **模拟题库选题** | 从 `<模拟题库根>` 挑一道，题干照录，用户确认后作答；**不**再自出题 | `"source": "模拟题库"` + `title_prefix` 可省略（默认「结构化每日一练：」） |

要求（自出题适用；真题库/模拟题库题干已固定，只做字数与可答性检查）：
- **题干必须 ≤80 字（硬上限）**——踩坑后立的规矩；超过 80 字阅读节奏断档、热点反差感丢失
- **选题优先从近期热点且适合结构化题目的话题着手**：先搜近期新闻/政策/社会现象，挑有矛盾张力、能多角度展开的题材；避免过于专业的岗位题
- 热点话题、政策类、社会现象为首选题材
- 避免过于专业的岗位题；用户指定岗位时按指定岗位出题
- **写完题干先 `len(question)` 自检**，**超就砍**，**别等用户指出**

**🔴 CHECKPOINT · STOP**：题干确认 → 用 `AskUserQuestion` 弹窗选项让用户确认（选项如："OK，继续"、"换一道"），**不要让用户打字**。用户选"换一道"→ 回到本步骤重出题/重选题。

### 步骤 1.5：审题 + 读方法论（写大纲前必做，🔴 本 skill 与"随手写一篇"的分水岭）

题目确认后**不要直接写大纲**。先做两件事，结论写给自己看（不进正文），但要落实到大纲和正文里。

**① 审题**——从题干逐项识别：

| 维度 | 要识别什么 |
|------|-----------|
| **设问** | 问的到底是什么（怎么看 / 怎么办 / 怎么组织 / 怎么沟通）？有没有"重点针对XX""你会怎么处理"这类限定？ |
| **身份** | 我在题里是谁（考生 / 事件当事人 / 某岗位工作人员）？权限边界在哪，哪些事不归我管？ |
| **对象** | 对谁说话、处理谁的什么诉求？多方诉求要逐一列出 |
| **限制条件** | 题干给定的事实与前提（资源、时间、已发生的事、矛盾现状）——正文不能丢、不能改、不能加 |
| **主要争点** | 这道题真正拉开差距的 1—2 个关键问题（如"程序正义 vs 名誉恢复""经营诉求 vs 居住安宁"）——正文优先答透的就是它们 |

**② 读对应方法论**——按题型读 `<方法论根>/各题型方法论/<题型>题_方法论提炼.md`（如综合分析读 `综合分析题_方法论提炼.md`），需要例题参照时再看 `<方法论根>/答题框架模板/答题框架模板_六大题型提炼.md` 和 `<方法论根>/讲义/` 对应章节。读完从中**选出本题适用的 3—5 项要求**带进写作，并想清楚每项为什么适用于这道题——不是证明"读过文件"。

**方法论取舍规则（重要，防止被带偏）**：
- 方法论是从样稿提炼的，里面的金句、排比、数字、场景是**可选技巧**：用不用、用几处，服从本题论证需要。文件里凡"每篇至少X个金句/排比/数字/场景"的频次要求，**一律不作硬性要求**
- 四项优先标准：**依据充分、推理成立、措施针对、表达清楚**——所有技巧服从这四项，冲突时砍技巧保论证
- 方法论里的示范句式、人物、数字在题干没有支持时，**不得当作事实材料或本人经历搬用**（"似真实"的引语也不能当事实写）

### 步骤 2：写大纲 + 答题初稿

把步骤 1.5 的审题结论落成大纲，再往正文承载块里装内容。**先组织逻辑，再写文字**。

#### 大纲要求（大纲是教学件，不是答案摘要）

- 写大纲时先在内部说明里标注**开场类型**（按题型三式选一）和**收尾类型**（判据式/总结式），并写明收尾预计汉字数落在 40—60 还是 80—100；正文按此执行，类型标记不写进学生可见的 docx 大纲区
- **破题角度**后用一句话说明**为什么从这个角度切入**：题干哪个信息、哪个争点决定的。让学员学到的是"换一道题怎么找角度"，不是背结论
- 三个核心观点要呈现**分析关系**（递进 / 并列 / 按时间轴），让读者看得出观点从哪来
- **不为凑三点灌水**：模板固定 3 个观点位，若素材只够两个实质角度，回步骤 1.5 换角度或换展开结构，而不是把第三个观点写成注水段
- 观点与正文三个 point 块一一对应；改稿先改大纲再改正文，两边保持一致

#### 正文承载与篇幅口径

- 正文承载块固定：opening → 第一/第二/第三（lead + body）→ closing
- **篇幅唯一口径：正文 = opening 至 closing 的汉字数（不含标点），不含题干与大纲，目标 700—800 汉字，硬边界 680—820**
- 低于 700 汉字先补论证和措施的适用条件，不是补套话；逼近 800 汉字优先砍次要措施；跌破 680 或超过 820 不得交稿
- **目标作答时长 210 秒（约 3.5 分钟，思考 30 秒另计）**：这是按字数折算的目标值，不是实测承诺；没有录音实测就不报告"X 分钟内能答完"

#### 核心观点展开方式（按题型选择，写大纲时定）

| 展开方式 | 适用题型 | 结构 |
|----------|---------|------|
| **3 观点结构** | 综合分析/自我认知/言语表达 | 3 个并列观点，每个有论据+论点 |
| **时间线结构** | 组织计划/应急应变 | 事前准备 -> 事中执行 -> 事后复盘 |
| **多维分析结构** | 综合分析政策类 | 个人层面 -> 社会层面 -> 政府/制度层面 |

选题后根据题型自动匹配展开方式，不要所有题都套"3 观点"。

#### 论证规则（综合分析从严，其余五类保底）

**综合分析按子题型**：
- **社会现象题**：解释现象**怎么形成、靠什么持续**（从激励结构、成本收益、信息差、监管难度等机制里挑本题最相关的说透），不能停在"这种现象不好"
- **政策理解题**：解释政策**作用路径**（改变了谁的成本/收益/行为，怎么传导到目标问题）和**实施条件**（钱、人、权责、配套），不能从"方向正确"直接跳到"问题已经解决/历史任务完成"这类大结论
- **观点理解题**：先解释观点的**含义和适用边界**（什么条件下成立、何时失效），再表态；不做单因归因，不下比论证走得更远的断言

**综合分析通用**：
- 核心判断要有题干事实、公认事实或完整推理链支撑；单个间接证据（如一处交易量数据）推不出制度性结论时，补齐中间环节或收窄结论
- **每条关键措施要能回答"它解决前面分析的哪个问题"**——对不上的措施砍掉或降为补充
- 一段话删掉题干关键词后仍能原样套进大量同类题，说明是模板段，重写

**其余五类（最低要求，细则读各自方法论）**：

| 题型 | 最低要求 |
|------|---------|
| 组织计划 | 明确对象、实施难点、资源条件和效果判断 |
| 人际关系 | 区分事实与猜测，沟通服务于解决工作问题，保留原则边界 |
| 应急应变 | 按紧迫程度安排动作，明确条件分支和本人权限 |
| 自我认知 | 用真实经历体现个人选择、行动与改变；**没有用户提供的材料时不冒写亲历** |
| 言语表达 | 直接进入角色，回应对象顾虑，不写成"我将如何沟通"的说明稿 |

#### 六条内容铁律（v1.5 新口径，逐条硬校验）

答题不是写作文，是"考场口述"。有观点、有逻辑、有表达、不套路、不假大空、接地气仍是底色；下面六条是能机检的硬线，违反任何一条即返工，不以"内容好"为由放行。除特别说明外，六条均针对**正文（opening 至 closing）**；大纲字段（破题角度、核心观点）保留原有标签格式，不受禁冒号约束。

1. **开场轮换**——按题型三式轮换（见下表），同批或近期同系列（有历史帖子可查时）同一开场类型不超过 60%，不默认"各位考官好"；首句直接进题眼，不先寒暄、不先复述题干。
2. **收尾轮换**——两型轮换：判据式 40—60 汉字（用一条标准或一句判断收束）／总结式 80—100 汉字（回扣主体三块再落一句判断）；末段整体 40—100 汉字，60—80 不设第三类（判据式超 60 按偏长、总结式不足 80 按偏短）。单篇按大纲选定一型；有历史帖子可查时，同批或近期同系列两种收尾都要有。
3. **三块封顶**——主体最多三块，多出的内容并入块内，不另开一层；本模板固定 3 个观点位，素材只够两块时换角度或换展开结构，不把第三块写成注水段。
4. **过渡句限额（说到底）**——全篇「说到底」≤1 次，能不用就不用。
5. **过渡句限额（不是…而是）**——全篇「不是…而是」句式 ≤1 次；其余翻案腔变体（不仅仅是…而是、并非…而是、不在于…而在于、与其说…不如说、表面…实际、看似…实则）一律 0。
6. **禁冒号/破折号**——中文冒号「：」、英文冒号「:」、破折号「——／—／--」一律 0（引出人物原话、网址、代码与机器字段除外）；列举改句号断句或"一是…二是…三是…"。

**开场三式与收尾两型（按题型选，同批/近期轮换）**：

| 题型 | 开场三式（任选，同批/近期轮换） | 收尾两型 |
|------|---------------------------|----------|
| 综合分析 | 判断式／场景式／设问式 | 判据式／总结式 |
| 组织计划 | 误区式／目标式／场景式 | 判据式／总结式 |
| 人际关系 | 情绪承认式／定性式／场景式 | 判据式／总结式 |
| 应急应变 | 优先级判断式／现场式／设问式 | 判据式／总结式 |
| 自我认知 | 故事切入式／判断式／设问式 | 判据式／总结式 |
| 言语表达 | 共情式／故事式／设问式（考官交代为固定外壳，不计入类型） | 判据式／总结式 |

单篇生成时按题型选一式一型；有历史帖子可查时，同批或近期同系列轮换，不连续重复。

**白话原则**：写完大声读一遍——读起来像"人话"再继续，读起来像"作文"就重写。冒号、破折号在生成阶段就不写，别等门禁阶段再清。


### 分题型高分要素差异化

不同题型考官看的核心不同，逐字稿侧重点要跟着变：

| 题型 | 考官最看重的 | 逐字稿侧重点 | 常见失分点 |
|------|------------|-------------|-----------|
| **综合分析** | 分析深度，透过现象看本质 | 重"本质+机制+对策"递进，观点要有判断力 | 停在现象层，缺机制分析 |
| **组织计划** | 流程完整性 + 可落地性 | 按"事前准备/事中执行/事后复盘"时间线展开，对策要有具体抓手 | 万能模板"领导交给我"，缺细节 |
| **人际关系** | 情商 + 原则性平衡 | 重"情理法"平衡：先理解对方 -> 再分析矛盾点 -> 给出兼顾方案 | 一味忍让或一味对抗 |
| **应急应变** | 轻重缓急排序 + 快速反应 | 按"止损/调查/处置/善后"优先级展开，先解决最紧急的 | 平均用力，没排序 |
| **自我认知** | 真实性 + 岗位匹配度 | 用具体经历支撑观点，不说空话"我很努力" | 假大空自我表扬 |
| **言语表达** | 感染力 + 对象感 | 有"对人说话"的对象感，不是背稿，注意语气身份适配 | 背演讲稿腔调 |
#### 公考面试用语禁忌（避免踩雷）

公考面试是正式场合，**用语得体、政治正确、考官听得进**——是比"有观点"更基础的红线。**4 类不要写**：

1. **不要带贬义色彩的比喻词**：落水狗、狼狈、龟孙、痛打、狼狈为奸等
2. **慎用网络流行词**：韭菜、小白、键盘侠、内卷、摆烂、躺平、yyds、绝绝子等
3. **慎用情绪化表达**：气死、笑死、巨坑、血亏、无语、离谱等
4. **不要有政治风险**："上面""领导拍脑袋""上面不作为"等不指明的吐槽；涉及民族、宗教、性别等要中性得体

**白名单替换原则**：
- 想用比喻 → 改成中性描述（如"落水狗"→"整治覆盖得了的只是显性摊位"）
- 想用网络词 → 改成书面表达（如"内卷"→"过度竞争"、"躺平"→"消极应对"）
- 想吐槽 → 改成建言（"运动式执法难持续"已经是建言式吐槽，OK）

**自检**：写完最后一遍**"考官读出来不得罪人"**——能过即可继续；任何一句读出来让考官皱眉或"笑场"，重写。

### 步骤 2.5：去 AI 味儿（电车站必选 + human-writing 门禁）

**硬流程：初稿 → 2.5.1 电车站诊断 → 2.5.2 电车站改写（独立会话/子代理）→ 2.5.3 human-writing check_prose 门禁 → 步骤 2.6 内容复核 → 才能进 pending_answer.json。三步缺一不可，电车站不得跳过；旧"可选/可跳过"口径全部作废。checklist 只在 2.5.1 诊断阶段读，步骤 2 写初稿和 2.5.2 改写阶段都不读。**

#### 2.5.1 电车站诊断（必做，读 checklist）

触发 `tramstop-skill` 模式一（诊断），先读 `references/checklist.md`（同仓库安装时位于 `../tramstop-skill/references/checklist.md`），再通读 8 个答题字段。按四层扫描：

- **经验层**：细节是否换成别的例子也成立；作者是否在场，判断有没有押注
- **结构层**：每段末尾是否硬落金句、是否有导游式路标、结尾是否完美闭环回扣升华
- **句式层**：否定排比、工整对偶、匀速句长
- **词汇层**：套话、AI 高频词

输出分层诊断报告：每个发现引用原文位置，按 **经验层 ≥ 结构层 > 句式层 > 词汇层** 排序，并回答三问——细节有几个可替换、判断有没有押注、删掉修辞后信息量够不够。诊断报告只作改写输入，不进正文。

#### 2.5.2 电车站改写（必做，独立会话/子代理，不读 checklist）

诊断与改写必须分离：改写用新的子代理或独立会话，只接收「诊断结论 + 初稿 + 题干事实 + 已核实素材」。**改写阶段不读 `references/checklist.md`**（白熊隔离），从"这道题真正要说什么"出发重写，而不是照着坏例子清单逐条删。环境不支持子代理时，至少分两轮独立执行：第一轮只做诊断并留下报告，第二轮改写时不携带 checklist 原文，只携带诊断结论。

按 `tramstop-skill` 模式二做结构手术和经验注入，边界如下：

- **真实素材只来自题干给定事实、用户提供的材料、素材库公开事实**；不得编造个人经历、数据、引语、文号、政策原话。没有素材时改用题干已有事实或定性表述，不硬编"人味"；确需用户补料的，在报告中写 `[待补：建议方向]`，**不得把占位符留在正文/成品**
- **不得改变题干事实与限制条件**；不得为了"人味"加与题无关的细节
- **保持正文承载块不变**：opening → 第一/第二/第三（lead + body）→ closing，主体三块封顶
- **反过度编辑**：奇怪但真实的具体细节、口语的重复、不完美的短句是真人证据，别当毛病修掉；看特征簇下判断，不凭孤例

#### 2.5.3 human-writing 门禁（必过，零硬禁词）

电车站改写稿必须过 `check_prose.py`，**硬停词、冒号、破折号、黑话、模型路标、套话开头/号召式结尾零命中才允许进步骤 2.6**。「不是…而是」≤1 是本 skill v1.5 的唯一豁免项，也是对 human-writing 全面禁翻案腔的唯一例外；check_prose 对该句式报「禁用翻案句」时，仅当全篇恰好 1 处且没有混用其他翻案句变体，才可按限额豁免并在报告中注明。把 8 个答题字段按 opening → point1_lead → point1_body → point2_lead → point2_body → point3_lead → point3_body → closing 拼成临时文本（不含题干/大纲/字段名），跑：

```bash
python3 -I "<human-writing目录>/scripts/check_prose.py" "<临时文本路径>"
# 同仓库安装时：../human-writing/scripts/check_prose.py
```

门禁标准：

- **硬停词 = 0**（说白了／说穿了／先说结论）
- **中文冒号「：」、英文冒号「:」、破折号「——／—／--」= 0**（引出人物原话、网址、代码与机器字段除外）
- **「说到底」≤1、「不是…而是」≤1**；「不是…而是」≥2 或混用其他翻案句变体 = 不通过；其余翻案腔变体 = 0
- **套话开头/号召式结尾 = 0**（与六条铁律的收尾规则一致）
- check_prose 的其他 WARN（句长、匀速感、抒情词等）按人工判断处理，不强制清零，但不得借"WARN 可放过"保留硬禁词
- 本 skill「公考面试用语禁忌」4 类继续有效；高风险公文词（深入推进/全面落实/持续优化/多措并举/综合施策/协同推进/切实保障/有效提升/有力推动）能换就换，不在 check_prose 硬停词里也要人工扫

**check_prose.py 不可用 → 🔴 STOP**：报告中标注门禁未过，不得进步骤 2.6、不得写 pending_answer.json、不得交付。没有"跳过门禁"的降级路径。

**门禁报警时逐条修（不是降级路径）**：
1. **删 AI 标志性短语**：搜索"标志着""彰显了""体现了""不断演变的""发挥了重要作用"→ 删除或改写为具体动作
2. **清破折号和冒号**：搜索"——""："与":" → 全部改逗号或句号（例外同上）
3. **改模糊归因**：搜索"专家认为""业内人士表示""有观点认为"→ 改为具体来源或删除
4. **破否定式排比**：除保留 ≤1 的「不是…而是」外，其余"这不仅仅是……而是……""不只……还……""表面……实际……"→ 改为直述句，判断从正面下
5. **重写空收束**：收尾只有"总之/综上所述"+空话时，改为有内容的收束（具体行动或价值落点），不强制固定开头词

**两条防过度修改的纪律（门禁后仍适用）**：
- **正常的三项列举不改**。"A、B、C"是自然的中文列举，只有当全文段落节奏机械雷同（每段都是同构三连）时才调整节奏，且不许因此增删内容
- **不强制固定收尾词**：收尾如果只剩模板腔（"总之/综上所述"开头、后面没有新信息），重写成有内容的收束；收束用什么词由内容决定，「说到底」全篇 ≤1，能用别的判断句就不用它

**门禁后自检**：
- 汉字数按步骤 2 唯一口径（opening 至 closing，不含标点）在 **700—800**，硬边界 **680—820**
- 六条内容铁律逐条过：开场/收尾轮换、三块封顶、「说到底」≤1、「不是…而是」≤1、冒号/破折号 0
- 读起来像"考场口述"而非"AI 生成文"；电车站诊断报告中的经验层/结构层问题已处理，且没有新增编造细节

详细规则参见 human-writing skill 的 SKILL.md（同仓库安装时位于 `../human-writing/SKILL.md`；若在其他位置则以实际安装路径为准）和 tramstop-skill 的 SKILL.md（同仓库安装时位于 `../tramstop-skill/SKILL.md`）。

### 步骤 2.6：改写后内容复核（必过，防"改写丢内容"）

去 AI 味儿是文字手术，可能顺手切掉论证。拿改写稿对照初稿逐项核对，**六项全过才进步骤 3**：

1. **事实与出处**：改写稿没有新增初稿没有的事实、数字、引语；引用性表述没有被升级为断言
2. **观点强度**：结论没有被放大——"有助于降低X"不能变成"X从此解决"，有条件的判断不能变成绝对断言
3. **因果链**：初稿的机制解释（为什么 → 怎么传导 → 所以）在改写稿里仍然完整，没有被压缩成口号
4. **动作与限制条件**：措施的适用范围、实施主体、"先A后B"的顺序没有被删改
5. **设问回应**：步骤 1.5 列出的每个主要设问/争点，在改写稿里仍有对应段落
6. **形式硬约束**：六条内容铁律逐条过——正文 700—800 汉字（不含标点，硬边界 680—820）、开场类型在同批/近期同系列（有历史帖子可查时）不超 60%、收尾落在判据式 40—60 汉字或总结式 80—100 汉字、主体三块封顶、「说到底」≤1、「不是…而是」≤1、冒号/破折号 0

任何一项不过：回到该句，先恢复它原本要表达的事实，再按 human-writing 规则重新表述——不是机械回滚，也不为凑禁令清零而牺牲内容。**改后只有换词变化、没有内容改善，不认定复核通过。**

**🔴 CHECKPOINT · STOP**：去AI味儿 + 内容复核确认 → 把电车站诊断/改写前后对比的关键改写点（3-5 处）和复核六项结论展示给用户，用 `AskUserQuestion` 弹窗选项让用户确认（选项如："够自然，继续"、"还是像AI，再调"），**不要让用户打字**。用户选"还是像AI"→ 重跑电车站改写或手动调整，并重走步骤 2.6。

### 步骤 3：写 pending_answer.json

按以下 schema 严格填写（与 `fill_structured_post.py` 的 `REPLACE_MAP` 对齐；含 `question` 与可选 `title_prefix`）。开场/收尾类型、电车站诊断结论只在大纲与报告中保留，不写入 `pending_answer.json`（脚本不消费）：

```json
{
  "source": "真题库",
  "title_prefix": "结构化历年考题：",
  "question": "题面文本（不带封面前缀）",
  "break_angle": "破题角度：...",
  "break_angle_reason": "切入理由：题干哪个信息/争点决定的",
  "core_views_title": "核心观点",
  "core_views_intro": "核心观点（3 个）：",
  "core_views": ["1. xxx", "2. xxx", "3. xxx"],
  "opening": "首段（破题后第一句）",
  "point1_lead": "第一，...",
  "point1_body": "展开论述...",
  "point2_lead": "第二，...",
  "point2_body": "展开论述...",
  "point3_lead": "第三，...",
  "point3_body": "展开论述...",
  "closing": "收束段（自然收口，不强制固定开头词）"
}
```

**【封面前缀铁律】** 封面文本框前缀由 `title_prefix` 控制，脚本会写入段[0] 两个镜像并按该值校验：

| 题目来源 | `source` | `title_prefix` |
|---------|----------|----------------|
| 热点自出题 | 可省略或 `自出题` | `"结构化每日一练："`（可省略，默认值） |
| **真题库选题**（`<真题库根>`） | **`"真题库"`** | **必须** `"结构化历年考题："` |
| **模拟题库选题**（`<模拟题库根>`） | `"模拟题库"` | `"结构化每日一练："`（可省略，默认值） |

真题库来源时**必须同时**写 `source` 与 `title_prefix`。`source` 含「真题」却漏传或传错前缀时，脚本直接报错退出，防止静默用错封面。模拟题库来源不含「真题」，脚本按默认前缀处理。报告里写明本次来源类型和封面前缀。

写入路径：`<项目根>/scripts/pending_answer.json`（**写之前先跑 Pre-flight #① 确认父目录**）

**【JSON 引号陷阱】**：JSON 字符串内部只能用**中文双引号""或转义符\"**，**不要用 ASCII 双引号嵌套**。推荐用 Python 生成：

```python
import json
data = {"question": "题干...中文双引号直接用"}
with open('pending_answer.json', 'w', encoding='utf-8') as f:
    json.dump(data, f, ensure_ascii=False, indent=2)
```
